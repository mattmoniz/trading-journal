# Scope: the autonomous / agentic trading system (2026-11-01, for DeepSeek review before any work starts)

The trader's words are in `docs/USER_REQUESTS_AGENTIC_20261101.md`. Summary of the wish: a system that assesses and fires, judges when to fire and when to hold, uses probabilities, quicker judgement, order flow and depth ("it can think and fire"); later reframed as an agentic AI built from DeepSeek, Claude and a local Raspberry Pi (Pi on hold for now); and the hard constraint "I need these trades done automatically, I cant participate in the trade selection". Earlier plan and DeepSeek's critique of it: `docs/AUTONOMOUS_BOT_PLAN_20261029.md` and `scratch/deepseek_response_bot_plan_20261029.md` (written when I wrongly said no depth data exists; it does, about 100 sessions).

## 1. What is true today (evidence the system would stand on)
- No rule has a demonstrated edge in dollars. With-trend counter-trend-spike rule: +12 per session in explore, sealed look 2026-11-01: relative to a time-matched placebo it passes (+22 per traded day, CI +2..+42, both halves) but absolute P&L is negative (-12.47 per trade, 20 percent win days). Claim `amt_marks_withtrend_holdout_rel_pass_abs_neg_20261101`.
- The AMT tell (live since 2026-10-28, Stage 2 sim orders running unchanged by user decision) is an EXPANSION detector, side a coin flip; trade test +1.93 per trade CI -3.44..+7.62; bracket (side-agnostic) and wait-for-break variants not shown; first 2 live sessions 16 trades, 14 stops, model P&L -454.50.
- Dozens of earlier order-flow, absorption, exhaustion, level-context, ML-gate studies NOT SHOWN (see CLAUDE.md "Where to look" and the research ledger). The live ML meta-labeling checkpoint adds no measurable value on unseen trades.
- Conclusion for the plan: today there is nothing profitable to automate by a smarter engine. What can be built is (a) the machinery that finds and vets rules honestly and (b) the operational safety layer any autonomous trader needs.

## 2. Existing infrastructure (read before proposing anything new)
DTC client and single centralized order path (`server/services/sierraChart/`: `orderSweep.js` sweepEntries/sweepExits, `reconciliation.js` broker-truth checks, `connectionManager.js`, kill switch in `orderEligibility.js`, daily-loss gate `dllGate.js`, `brokerAttention.js` banner); live setups roster with SUPPRESS/PROMOTE pipeline and LIVE_ROSTER gate; `scripts/amt_tell_live/` Python sidecar supervised by `server/services/amtTellServiceManager.js` (replays the research code literally; parity harness `parity_day.py`); `scripts/amt_marks_live/` (prefix-safe context features, live-vs-replay causality parity gate with a mutation test, versioned calibration store, no-order guard, `docs/MARKS_BUILD_FRAMEWORK_20261029.md`); research ledger tables (`performance_audit` RESEARCH_CLAIM / OPEN_DECISION via `record_claim.mjs`, `flag_decision.mjs`); pre-registration + sealed hold-out lock-file discipline; DeepSeek (design critique and code review, no DB), Gemini (DB mining, quota-limited), Claude (build, run, audit). Authority asymmetry: the system may halt unilaterally; only the user arms (sim profiles have an explicit auto-rearm allowlist `DTC_AUTO_REARM_SAFE`).
Failure modes that already bit this system (CLAUDE.md): positions misattributed across strategies sharing one account/instrument, phantom fills, stale price feed, machine sleep (WSL2 full outage), mid-session restart (restart disarms), duplicate server processes from backgrounded scripts, refused-and-retried exits firing on an unrelated later position, gates that fail closed without saying why, a later override silently winning over an earlier one in a live-eligibility chain, a status banner that hides on error.

## 3. Candidate architectures (DeepSeek: critique, pick, or replace)
A (my recommendation). Deterministic, replayable DECISION ENGINE that fires only rules which passed the evidence stages, plus OFFLINE research agents (DeepSeek and Claude) that find, pre-register, test and audit rules; no language model in the firing path. The Pi, if used later, hosts monitors and archives only. Probabilities appear only as a calibrated score or an abstention rule on top of a rule that already has an edge.
B (the trader's original wish). An LLM agent in the loop that reads the live state and decides fire / hold / size ("think and fire"). Concerns to test against: seconds of latency, non-determinism (no byte-replay, no parity gate), no calibration, cost, prompt injection from data, rationalisation, and no way to give it a pre-registered evidence record. Possible bounded roles to evaluate: a pre-session briefing that chooses among pre-approved rule sets within hard limits; a post-session reviewer; nothing with order authority.
C (minimum). Research agents only, no live component beyond the existing sim tell. The honest fallback if A's gate (an edge) is never met.

## 4. The research-agent loop (the part that can be built now)
Hypothesis registry, then a pre-registration committed before any outcome, then a pinned-window run of code only, then an audit by the other model that re-derives the headline number independently, then a claim or decision record, then promotion through stages: research (explore data) to forward SHADOW (logged beside live, zero order impact) to SIM orders (self-pausing) to a user decision for real money. Dangers specific to an agent factory: a false-discovery machine (thousands of looks), spent hold-outs, a "winning" rule that is a selection artefact, an agent editing live config. Required design elements to be proposed and reviewed: a global LOOK LEDGER (count of every look per data window, multiplicity budget, sealed hold-out single-look guard files as exist today), a pre-registered promotion rule (dollars not relative skill, day-blocked CI, halves, forward shadow floor), change control (no rule, window or stop change while an evidence count runs; a new written decision restarts the count), and which steps may be fully automated (running a pre-registered script, recording claims) versus human-gated (choosing a new hypothesis family, spending a hold-out, any real-money step).

## 5. Gates before any autonomous firing
G0 operational truth layer audited against the failure modes above (position attribution, broker reconciliation each poll, stale-feed / sleep / restart fail-closed re-derive from broker, per-session arming, kill switch and daily-loss gate verified fail-closed on boot, parity gate as a blocking startup check). G1 a rule with an edge IN DOLLARS: explore, then a sealed look, then forward shadow floor. G2 sim orders with self-pause and a written review rule. G3 evidence floor reached on sim (the tell's is about 150 trades). G4 a user decision for real money; nothing here assumes it.

## 6. Phases and size (working sessions, my estimate)
P0 gap audit of G0 against the repo (1). P1 look ledger + hypothesis registry + runner for pre-registered scripts, wired to the existing claim/decision tables (2-3). P2 shadow decision-engine skeleton reusing the marks framework parity gate, logging only (2-3). P3 route a rule that passed G1 to sim through the existing `sweepEntries/sweepExits` path, no new order code (1-2). P4 Pi monitors and depth archive (on hold). Parallel research that feeds G1: the direction program and the tell-as-roster-context study in `docs/SCOPE_HARD_TODOS_20261101.md`.

## 7. Kill rules
If the direction program and the roster-context study both fail their pre-registered tests and the Stage 2 review at the floor shows no edge, the autonomous TRADING engine is not built; P1 (the honest research loop) and P0 (operational safety) still stand. No step spends a sealed hold-out or arms anything without the user.

## 8. Questions for review
Is A the right architecture and where, if anywhere, does a language model belong? Is the research-agent loop's false-discovery control sufficient? Are the gates G0-G4 the right ones and in the right order? What is missing, unrealistic or should be cut?

## 9. DeepSeek review outcome (received 2026-11-01 22:50-23:10 UTC; full text `scratch/deepseek_response_scope_review_20261101.md`; audited by Claude against the files)
Accepted (verified or well argued):
- Architecture A confirmed; C is the only honest fallback; B (an LLM that thinks and fires) rejected as the firing path because an LLM cannot be given a pre-registered evidence record and cannot have a sealed look, which is the failure the with-trend rule just showed. An LLM is allowed offline only (hypothesis generation, code review, independent re-derivation, post-session explanation); a pre-session choice among pre-approved rule sets is the ceiling and must emit a versioned, replayable rule-set id.
- The trader's pasted prompts: right about the Sierra export traps (start-of-bar timestamps, export type, back-adjustment, already item 4(d)); wrong for this repo because they assume a tradeable prediction exists (XGBoost, RL, LSTM, PCA, 15-minute bars, a 36-cell plateau grid; verified present in the pasted text) and the grid-plus-verdict machine is selection on the hold-out.
- The research-agent loop needs a GLOBAL, machine-enforced look ledger, not per-rule files: count every contact with a window's outcome labels (descriptive peeks, sensitivity runs and horizon variants included); explore looks multiplicity-corrected (Benjamini-Hochberg per family plus the day-block permutation null); the sealed hold-out a spend-once-per-family resource. A code guard (`HOLDOUT_OK`) is bypassable by an agent. Claude's addition after checking: the post-2025-05-16 sessions for the price_bars-based studies sit in the live database, readable by any script, so real protection needs an access gate (a read-only agent role or a view cut at the explore date) plus a runner that refuses a hold-out read without a ledger look id.
- Power: the full-set interval is about +/-5.5 dollars per trade; the "+/-20" I quoted for the 324-fire split is the +/-22 half-width of the paired AGREE-minus-DISAGREE difference, not a subgroup mean (run_direction R4: -14.09, CI -36.91..+7.47); a 324-fire subgroup cannot show a 5-10 dollar edge.
- Direction program: re-anchor on the verified market-behaviour results (first-break side, near/far, both partly mechanical) and drop the already-null flow cues; every direction claim must beat opposite-of-tell AND a random-direction placebo AND a sealed look; kill rules per cue and on ABSOLUTE dollars (the 2026-11-01 lesson), not relative to a coin flip. Item 2 (tell as roster context): kill rule on absolute P&L, not MAE/MFE; real vs BACKFILL separated.
- G0 is a STANDING invariant, not a one-time checklist: daily broker-truth attestation re-deriving live P&L from reconciliation, the parity gate as a blocking startup check, a visible reason on every fail-closed gate, mutation-tested parity for every new live feature.
- EV per session: G0 hardening about equal to item 4(a) (write the Stage-2 review rule before the floor), then item 2, then item 1, then item 3, then item 6. G0 first because its value does not depend on finding an edge.
Overstated or not adopted without the user:
- "DTC_AUTO_REARM_SAFE contradicts only-the-user-arms, remove it": the flag is a documented, explicit user-requested exception (2026-10-11), limited to profiles whose files say sim; the scope already disclosed it. DeepSeek's diagnosis (it weakens the asymmetry) is fair and is a USER decision whether to keep it; nothing removed.
- "The balance-vs-trend cue needs a new tuned 65-point detector": inaccurate, the 65-point rotation detector and `amt_daily_state` already exist; the point that it still adds looks stands.
- Dropping the delta cue entirely: my delta read was ours, not the trader's DDY heatmap; the exact DDY version is untested, but the prior is low, so it ranks last.
Revised order (supersedes section 6 and the recommended order in SCOPE_HARD_TODOS): (1) item 4(a) Stage-2 review rule written now and G0 gap audit plus the standing-invariant design (P0), (2) the look ledger and runner gate (P1), (3) item 2 tell-as-roster-context on absolute P&L, (4) item 1 direction program re-anchored on first-break / near-far with per-cue absolute kill rules, (5) depth waits, marks residue parked, architecture B not built.
