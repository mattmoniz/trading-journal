# Scope of the hard todos (2026-11-01)

Situation: the AMT tell is a measured EXPANSION detector (price travels about 18 percent more in the next 5-60 minutes, ladder adds 9-13 percent beyond the flow components) with a side that is a coin flip (claims `amt_tell_is_expansion_detector_side_not_shown_20261101`, `amt_tell_expansion_5_15_30_60min_windows_20261101`, `amt_tell_direction_delta_flow_not_shown_20261101`, `amt_tell_first_break_side_above_control_20261101`, `amt_tell_armed_wait_for_break_entry_not_shown_20261101`, `amt_tell_bracket_5_15_30_exits_not_shown_20261101`). Stage 2 (sim-account orders on the tell) is running unchanged by user decision (`amt_tell_stage2_leave_running_review_at_floor_20261101`). The with-trend marks rule passed its sealed look only relative to a placebo and lost money in dollars. The trader needs trades fully automatic, so a human side read cannot be part of the system. Sizes below are my estimates, in working sessions (one long sitting each); probabilities are subjective.

## 1. Automatic side rules from the trader's cues (the direction program)
Goal: a rule, computed from data available at the fire, that chooses LONG / SHORT / SKIP at tell moments and beats the tell's own direction and a coin flip after costs. Hardest and highest upside; subjective chance of a net-profitable rule: about 10-20 percent.
Why hard: only ~1,760 fires (about 2,600 decision points) on 488 dates; tested so far with no effect: a 10-bar delta read, a delta flip, the with-trend rule in dollars; a near/far-edge geometry effect exists but is partly mechanical and post-hoc. Every extra cue is a new look.
Cue to measurable feature (each needs a frozen definition before any outcome): (a) delta flip: the user's DDY Delta Heatmap settings, else our own; (b) absorbed/defended area: the repo absorption marks (`scripts/amt_absorb`) and node/profile features (distance to POC and to a high-volume node edge, whether price is at one); (c) peak-and-fail at an overnight/IB edge: the failed-break-back context (53 percent of fires; needs the missing matched control); (d) balance vs trend day: intraday rotation count (65-point detector), range so far against ATR20, drift sign (daily `amt_daily_state` is too coarse); (e) near/far edge (DeepSeek says the tell's lift is in the FAR cell); (f) stuffed big orders: depth sessions only (item 3).
Phases: P0 write the feature dictionary and a hypothesis list of at most 8, with a multiplicity budget (Benjamini-Hochberg across the list), before any outcome (1 session). P1 market-behaviour tests first (first-break side and 15/60-minute signed move per cue against matched controls, day-blocked CIs) (1-2 sessions). P2 only survivors: trade simulation with realistic fills, one position at a time, expanding walk-forward, day-block label-permutation null (the repo convention), compared with a plain regularised model on the same features (1-2 sessions). P3 forward shadow: log each candidate rule's side beside every live tell fire through the running sidecar, zero order impact; this accumulates real forward evidence without touching Stage 2. P4 one sealed look: the AMT-tell hold-out (sessions after 2025-05-16) is NOT extracted; extraction is hours of compute and spends the look, so only for a rule that survived P2.
Resolution to quote: full set about +/-5 dollars per trade, a 324-fire subgroup about +/-20; effects under about 8 dollars per trade over the whole population cannot be seen.
Kill rule: no cue clears its pre-registered test in P1 -> the direction program stops and the tell stays an expansion tool.
Needs the user: DDY settings (or "use yours"), OK to use the repo absorption marks as "absorbed area", later a go for the hold-out extraction.

## 2. The tell as context for the roster that already trades automatically
Goal: use "expansion is likely" to change risk handling of existing automatic setups (stand aside for fades that expansion runs through, wider stop, smaller or larger size). Needs no side edge; subjective chance of a usable effect: about 30-40 percent.
Why hard: (a) the tell state must be rebuilt causally at each roster fire time from stored 500-volume sessions, with the prefix-invariance parity test (the marks framework has the pattern); (b) the roster history is mostly BACKFILL simulation, with `origin_status`, `is_cluster_primary` and `REAL_TRADE_FILTER` pitfalls and the roster-churn confound; (c) research tell data is RTH 10:00-14:30 only, Globex is untested and CLAUDE.md requires both; (d) expansion raises both MFE and MAE, so the sign of the effect on a fade is not known in advance.
Phases: P0 build `tell_state_at(ts)` and its parity test (1 session). P1 descriptive: outcome, MFE and MAE of roster trades with the tell active in the prior N minutes versus not, within setup family, real and backfill separated, day-blocked (1 session). P2 counterfactual rules on the same trades with realistic fills (skip, wider stop, half size); paired, not split, comparisons (1 session). P3 forward shadow tag on live roster fires. Globex arm: separate tell state and test (1-2 sessions) or an explicit flagged decision that it is untested.
Kill rule: no effect on MAE, MFE or P&L of roster trades given tell state in P1 -> stop.

## 3. Depth, stuffed orders and peak-and-fail

DeepSeek's floors: >= 50 qualifying events on >= 30 sessions to describe, >= 100 on >= 60 to infer; the conjunction is rare, so likely unmet for months.
Plan: keep recording and keep the files (check disk space; the Pi archive is on hold); define the signature and a validation pilot on the existing sessions (1-2 sessions, per-second summariser `scripts/depth_persec_20261021.mjs` and reader `scripts/depth_absorption/depth_reader.py` exist); recheck when the session count reaches about 200 (roughly early 2027 at about 21 sessions a month). Earlier trade-tick versions of stuffed orders were NOT SHOWN, so the prior is low. Needs nothing from the user except leaving recording on.
