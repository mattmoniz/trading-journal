13. **`price_bars_primary` (NQ) has only ONE bar per calendar day — not real intraday density — from 2022-12-14 through 2023-11-14, immediately before the already-documented ES-symbol-contamination window (item 12's neighbor, 2023-11-15 to 2023-12-15).** Found 2026-08-11 auditing an ATR-compression-breakout pilot: a suspicious identical sample bar appeared at the same timestamp across two differently-aggregated bar widths (15-min vs 30-min), which shouldn't happen — traced to a direct per-day `COUNT(*)` showing avg 1.0 bars/day every month Jan–Oct 2023, jumping to ~630 bars/day starting Nov 2023. Real usable NQ intraday history is therefore ~2.5 years (starting 2023-12-16, right after the ES-contamination window), not the ~3.7 years the raw `MIN(ts)`/`MAX(ts)` range implies — any script that queries `price_bars_primary` from an early-2023-or-before start date without checking density will silently treat single daily snapshots as sequential intraday bars, corrupting any rolling-window computation (ATR/TR, rolling range, etc.) that spans the transition, and skewing where any bar-count-based warmup/lookback period actually lands in real time. Confirmed this actually happened: an ATR(20)/ATR(30) warmup and the first ~230 bars of a 60-min backtest were built on this degenerate stretch, materially changing results once excluded (`scripts/pilot_atr_compression_breakout.mjs`/`_mtf.mjs`, `atr_compression_breakout_60m` `RESEARCH_CLAIM`, corrected same session). **Not fixed at the source** (no code bug — this reflects a real gap in the underlying Sierra Chart export data for that period, same category as item 12's rollover gaps) — the fix is per-consumer: any new script reading `price_bars_primary` with an early start date should check `GROUP BY ts::date, COUNT(*)` for the intended range first, or default to `ts >= '2023-12-16'` unless it specifically needs to reason about the sparse pre-Nov-2023 daily-only period. `data_sanity_audit.mjs`'s standing checks do not currently catch this (they check for outlier bar VALUES, not density/gaps in bar coverage) — worth extending in a future session, not done here.
