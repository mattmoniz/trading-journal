# Design review — FLOOR_CONTEXT_NARROWING_PREREG_20261026

1. **There is no true hold-out; the "confirm" split re-reads data the parent already saw (most serious).** The events, the outcome (E2 = AGREE−DISAGREE ret60 inside the parent strata), and the Session context are all recycled from the parent study, which already (a) required the same sign in both chronological halves for E2 SHOWN and (b) reported RTH/Globex separately (E3d). So a CONFIRMED Session=Globex cell just re-discovers the parent's own descriptive split — the exact forking path this protocol claims to prevent. Fix: make the only confirm gate genuinely unseen forward days (the nightly ES refresh), and demote Session to descriptive-only (or drop it from the confirm count).

2. **The hold-out is structurally underpowered for the primary outcome E2.** Hold-out ≈ 40% of ~365–408 days (~150 days); a tercile cell ≈ 50 days; DISAGREE is 18–28% of fires ⇒ well under the 30-DISAGREE-event floor per cell. Nearly every E2 cell will be labeled UNDERPOWERED, so only E1a cells (a different question) can CONFIRM. Fix: precompute expected per-cell hold-out N and smallest detectable effect up front; if E2 can never clear, say so, and either pool terciles or widen to 2 levels so E2 is actually confirmable.

3. **The 44-cell count discloses multiplicity but does not control it, and it is internally inconsistent.** Session, relative-volume, session-volume, and volatility are mutually correlated, and long/ceiling plus E1a/E2 overlap, so false candidates cluster: sibling cells co-confirm spuriously, and "44 × 0.025 = 1.1" is not the effective independent-test count. The doc also mixes "95% CI" (⇒ 0.025 one-sided lower bound) with a CANDIDATE rule using only the lower bound. Fix: pin alpha once, use a single joint max-stat permutation null over all 44 cells rather than per-cell tests, and print the pairwise context-overlap matrix so correlated CONFIRMEDs are not counted as independent.

4. **Lookahead ambiguity in the volatility regime, and frozen cut points silently misclassifying hold-out events.** "The entry date's A15 ranked within the previous 250 days" can read as using the entry day's full 15-minute range (post-fire minutes leak in). Separately, explore-only tercile cut points are frozen onto hold-out where the volume distributions have drifted, emptying or misassigning cells — safe when it reads UNDERPOWERED, but it can also flip a marginal cell. Fix: define A15 strictly as-of the fire bar (prior day + completed bars only, rank window frozen to the prior day), and report cut-point values and per-cell N in explore vs hold-out.

5. **CANDIDATE→CONFIRMED bakes in the winner's curse.** Surviving a 44-cell explore screen biases the hold-out estimate upward; requiring hold-out point+CI>0 does not remove that selection bias, so a CONFIRMED can still be a false positive well above its nominal rate. Fix: test the hold-out against a permutation null computed on hold-out (or shrink the estimate toward the pooled prior), not a pointwise >0 rule.

6. **A CONFIRMED can answer the wrong question.** The rule lets an E1a (entry-worthwhile) or ceiling-mirror cell CONFIRM and be reported as "the context works," even when E2 (does ES agreement add value — the actual question) does not. Fix: require E2 to CONFIRM for any ES-agreement claim; label E1a confirmations as a different question and never blur them into "ES agreement works here."
