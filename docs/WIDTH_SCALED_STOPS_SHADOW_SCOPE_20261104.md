B. **Explore decision test (pre-registered before any outcome is read; ledger look first):** does stop = k x forecast width beat the fixed stop it replaces, on (i) the overnight order-flow nights (flow-sign trade, 00:00 entry, stop 400 or 300, exit 14:30; the 87 research-rule nights and the 863 all-nights set) and (ii) the shadow pool (real ACTIVE+SHADOW fires, `is_cluster_primary`, `origin_status` not BACKFILL, hr-006/007) re-simulated with stop and target scaled by forecast width over the day's typical width? k is NOT tuned: the one value that reproduces the current average stop on the explore population (so the arms differ in how stops VARY with the day, not in how wide they are on average; cv-026), plus the ratio form for targets. CONTROLS (hr-041/042): (a) the same scaling with a PLAIN width proxy (prior-20 ADR; overnight range so far for the 00:00 version) to show the forecast adds something beyond persistence; (b) a placebo with a random day's width (cv-029); (c) fixed stop. Outcome: mean dollars per trade, worst loss and win rate, paired per trade, day-block 95 percent CI, detectable effect printed first, both chronological halves.
C. **Forward shadow arms (only if B shows a lead, or the user wants the forward record regardless):** a fifth arm WIDTH (and a control arm ADR) in the existing `ovnArms` tracker (`server/services/ovnArmsSummary.js`, same fills, same forward nights from 2026-11-02) and a read-only forward re-simulation of every new shadow-pool fire with the width-scaled stop and target next to the real outcome (new table or computed from `active_setups` + bars, decided with the DeepSeek review). Monitoring cadence ('monitor it closely'): the card shows N, mean, CI and the control arms every day; a written look at N = 15 and 30 qualifying events (overnight arms) and N = 30 and 60 fires (pool); a post-deploy watch of the first live nights (parity, no AMT or detector alarm, rows written) as for every change; a weekly line in OPEN_THREADS until the rule resolves.

## 2. Timing, stated before it surprises anyone
The overnight arms qualify on about one night in ten (87 of 878 exported nights), so N = 15 takes roughly 7 months of forward nights; the 863-night all-nights set and the shadow pool are what give an answer within weeks. A forward result on the overnight arms alone is slow by construction.

## 3. Rules (written now)
LEAD: B shows the forecast-scaled arm beats BOTH the fixed stop and the plain-width control with the CI lower bound above 0 in both halves. FAILED: the forecast-scaled arm does not beat the plain-width control (the forecast adds nothing beyond persistence) or the CI includes 0 with the detectable effect printed; then retire (register row 4 retire rule) and keep the forecast only as a display. Autopsy (co-022): which population failed, whether the forecast or the scaling idea failed, the cheapest next test. Hold-out: NOT touched in B; ONE sealed look only if B shows a lead, spent via `spendSealedLook()` (hr-023). Globex: the overnight arms ARE Globex entries, the pool is RTH-heavy; the pool's overnight rows are split out (hr-002, hr-039).

## 4. Risks and limits
The forecast explains about 11 percent of the squared error of the range ratio, so a stop scaled by it varies only modestly from the ADR-scaled one; the tell fires after 10:00 when part of the range is known (the pool and overnight arms share this to differing degrees); the pool mixes setup families with different stop logic (a stop scaled by width may be wrong for a level fade whose stop is structural, cv-002); the overnight edge itself only shows in 2026 (`ovn_orderflow` addenda A2-A4), so a width scaling cannot rescue a population with no edge outside that era.

## 6. A1. Amendment after DeepSeek design critique round U (2026-11-04 ~16:45 ET; `scratch/deepseek_response_20261104_152602.md`; written before any outcome was read or any code written)
Diagnoses taken; where a remedy is not taken the deviation is stated (hr-035).
1. **Control (a) was the wrong control.** The forecast's own baseline already carries weekday and prior-day range ratio, so a win over flat ADR could be volatility clustering. The control arm is now stops scaled by the BASELINE model's predicted width (weekday + prior-day range ratio, `daytype_forecast.py` BASE); the forecast must beat THAT. The flat-ADR arm stays as a second, weaker control.
2. **Expected size, stated before the test (DeepSeek's reconstruction, to be replaced by the printed number):** a 10.7 percent squared-error gain is a correlation of about 0.33 on the residual, so the forecast moves the stop by only about 10 percent (about +-40 points on a 400-point stop), while the overnight arm's profit sits in its wide-stop survivors. The idea is under-powered by construction; the decision test below is cheap precisely so it can fail early. The detectable effect and the actual stop-width spread are printed first.
3. **k:** one k PER arm (400 and 300 are separate), each set so the mean stop on the explore nights equals the fixed stop; win rate, mean loss and stop-out share are reported SEPARATELY, not just paired net (cv-026).
4. **Targets dropped from the test.** The overnight arm has none and every target tested on the tell clipped the extensions; no target arm unless the user asks, and then only with a fixed externally chosen multiple and an asymmetric-geometry placebo (cv-022, cv-029).
5. **Population: the all-nights set only (and its legs >= 6 subset); the heterogeneous pool is dropped as a verdict** (structural stops, about 80 percent BACKFILL: cv-002, hr-006) and kept as a descriptive cross-check at most. DeepSeek proposed restricting to the tell; NOT taken: the user's question was explicitly not the tell, and the tell's node stop is structural (a width stop vs a node stop is a different test, parked).
6. **00:00 model:** a refit on truncated overnight features (through 23:59) is its own pre-registered model, not a reuse of the 09:30 fit; if it cannot be fitted cleanly the 00:00 arm is dropped.
7. **STRUCTURAL LIMIT found while applying this:** the forecast was developed on the 522 explore sessions (2023-03 to 2025-05-16) and its hold-out is UNSPENT; the overnight order-flow edge exists almost only in 2026 (legs >= 6 nights: 2023 none, 2024 four, 2025 nineteen, 2026 sixty-four), which is the forecast's hold-out era. So the explore test has few qualifying nights and the decisive test is the ONE sealed look on 2026 (`spendSealedLook()`), spent only if the explore test is not clearly dead and only after the explore code has been run end to end as a separate passing command (cv-111).
8. **Escape hatches closed.** 'Forward record regardless' is allowed but is labelled DESCRIPTIVE and cannot upgrade a FAILED B to a LEAD; the card's Next line carries a pre-committed rule: FAILED if the forecast-scaled arm does not beat the baseline-width control with a CI lower bound above 0 and the same sign in both halves; then retire to a display and write the autopsy (which component failed) and do not spend the sealed look.
