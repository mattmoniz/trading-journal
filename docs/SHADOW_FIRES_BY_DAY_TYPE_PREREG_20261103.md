# Pre-registration (descriptive, informative): the shadow (would-be-live) fires by setup, time of day and the shape of the day (written 2026-11-03 night BEFORE any outcome was joined to a day type)

STATUS: FROZEN. User request (2026-11-03): "shadow sim trades... which setups or times had the best trades with which day type; just informative; I want to see all fires." Descriptive, hindsight (the day's FINAL profile), uncounted for any gate; ledger family `shadow_fires_by_day_type_20261103`. Nothing here changes what the system trades.
## 1. Fires
`active_setups` rows with origin_status IN ('ACTIVE','SHADOW') (the would-be-live fires, ACTIVE = real sim orders), fired 2026-07-09 onward (BACKFILL excluded: synthetic), excluding the 16:00-18:00 ET rows fired 2026-07-09..2026-09-16 (post-close flood, cv-051) and any row with a *_basis flag; only rows with an `actual_pnl` (NOT_FILLED / unresolved have no trade); dollars per fire as stored (1 MNQ). PRIMARY LENS = declustered (is_cluster_primary = true, the user's default lens); the CSV carries ALL fires with the flag. A fire's day is its `trade_date`; a Globex fire is compared with that trade date's RTH shape (hindsight).
## 2. Day type (frozen)
FINAL RTH profile of the trade date via `profile_shape.features`: letter D / P / b (value-area midpoint in thirds) and the multi-hump flag (bimodality >= 0.365); day type = letter plus 'multi' when flagged (e.g. D, D multi, P, P multi, b, b multi); also strong B (>= 0.61). Exact 500-contract bars with volume at price through 2026-10-19 (`scratch/volbars500_holdout_20261103`), 1-minute bars with volume spread over each bar's range after that (shown equivalent on 8 of 8 overlap dates).
## 3. Time blocks (ET, of the fire time)
RTH: open hour 09:30-10:30, 10:30-12:00, 12:00-14:00, 14:00-16:00. Globex: 18:00-00:00, 00:00-03:00, 03:00-08:00, 08:00-09:30.
## 4. Outputs (N, days and the day-block 95 percent CI of the mean printed; N below 20 or fewer than 4 days is never ranked)
O1 fires, days and mean per day type; O2 time block x day type; O3 setup type (N >= 20) and setup FAMILY (direction and OVERNIGHT stripped, N >= 30) overall; O4 setup family x day type and setup type x day type cells with N >= 20 on >= 4 days, ranked best and worst with a SPLIT-HALF check (first vs second half of the dates: same sign?) and the NUMBER OF CELLS EXAMINED, because the best of hundreds of cells looks good by luck; O5 setup family x time block. The full fire list is written to a CSV. A top cell is a hypothesis for a pre-registered forward test, never a finding.
## 5. Limits
93 trade dates, so far fewer independent observations than fires (fires on one day are correlated: day-block CIs); the period (Jul-Nov 2026) is one regime; day types are hindsight; the SHADOW pool is mostly gating (cluster, direction, cooldown) rather than immature setups; synthetic or MARK_TO_MARKET resolutions are kept but flagged in the CSV.
