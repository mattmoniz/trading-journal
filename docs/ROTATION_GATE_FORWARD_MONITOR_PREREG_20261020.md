# Pre-registration: forward monitor of the rotation-direction gate and its context variants (written 2026-10-20; the forward window starts 2026-10-21 so nothing in it has been seen)

Why: the fixed 65pt gate failed the 3.5-year level-fade replay (4 of 5 criteria; Claude and Gemini agree) and its live tags are mixed (8 days: AGREE better on 3 of 8), but (a) a larger scaled gate (k=0.3 x ATR20, about 105 points now) was positive in every explore/hold-out/year slice of the replay (each CI includes zero) and (b) on 2,203 live roster rows (35 dates, 2026-08-15..10-19, RTH, primaries, exploratory) the fixed-65 AGREE minus DISAGREE was -22.1 (CI [-39,-5]) when the dashboard EXPAND composite was in its LOW third and +9.9 / +13.2 in the MID / HIGH thirds. 35 days is too short for a hold-out, so the only fair test is forward data. No live code change is needed: the gate direction at each fire is reconstructable from bars, so a script evaluates new live rows with frozen definitions.

## Frozen definitions
- Population: `active_setups` rows with fired_at >= 2026-10-21, RTH entry 09:35-15:59 ET, origin ACTIVE or SHADOW, is_cluster_primary true/null, actual_pnl not null, resolution_method not MARK_TO_MARKET/RECOVERY_MTM, direction from the setup_type (LONG/SHORT), excluding `isRotationGateExempt()` types (BRACKET_BREAKOUT_LONG, MAJOR_PIVOT_DEFENDED_BREAK_, RTH_FLUSH_, GLOBEX_FLUSH_) and POC_ROTATION_JOIN. Model P&L (actual_pnl).
- Gate G65: AGREE = the in-progress 65pt leg direction (rotationDetector.detectRotationLegs, 18:00-anchored session, legs confirmed by the fire bar) equals the trade direction. Gate G30: the same with R = 0.3 x ATR20(trade date) (ATR20 = mean RTH range of the 20 previous sessions).
- Context: `vol_building_signal.compositeStrength` stored on the row (the dashboard EXPAND gauge input); LOW/MID/HIGH thirds use FROZEN cut points = the 33rd and 67th percentiles of compositeStrength over the live roster rows of 2026-08-15..2026-10-19 (computed by the script from that fixed window, never refreshed). Also momentumContext ACTIVE/QUIET (stored) and PDX (close beyond the prior-day high or low from level_prices).
## Rules judged (only these)
- R1: G65, all rows (baseline). R2: G30, all rows. R3: G65 restricted to rows with EXPAND composite above the LOW third (MID or HIGH).
## First formal look and pass criteria
The first look happens only when there are >= 20 distinct forward trade dates AND >= 300 decided rows on each of the AGREE and DISAGREE sides of the rule being judged. Before that the monitor prints counts and NO DATA YET. At the first look a rule PASSES if AGREE minus DISAGREE per trade > 0 with the day-blocked 95% CI (2000 resamples) excluding zero AND positive in both chronological halves of the forward window. R3 is judged against R1 (R3 must beat R1 on the same rows). Nothing is promoted automatically; a passing rule becomes a user decision (SHADOW tag first). If R1-R3 all fail at the first look, the gate stays tag-only and the context idea is closed at these definitions. Weekly rerun via scripts/run_weekly_backtests.sh; the latest numbers are persisted with recordClaim (`rotation_gate_forward_monitor_20261020`, recheck due 30 days).
