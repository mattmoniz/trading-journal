NQ Signal Arbitration and Continuation Model: Implementation Specification (v2)
Purpose: Two distinct capabilities layered on top of the meta-labeling filter:

Direction lock — prevent the system from firing opposite-side signals while a trade is committed to a level. Pure logic, no ML.

Continuation model — decide whether an open trade at its calibrated target should be held for further extension or exited. LightGBM classifier.

Both depend on the raw_signals, signal_features, signal_labels tables and the feature snapshotter from META_LABELING_SPEC.md. Do not begin this spec until the meta-labeling spec is fully implemented and the meta-labeling filter is live or in stable shadow mode.

Stack: Same as meta-labeling spec. Express (3002), Python microservice (5001), PostgreSQL trading_journal.

Non-negotiable principles:

Direction lock is a signal-level filter, not an execution change. It vetoes signals before they reach execution.

The continuation model never widens risk. It can only decide to hold a runner that already has stop at breakeven and 50% booked. It cannot add to a losing position.

All decisions are logged. Every veto and every hold is a row with a reason.

All timestamps UTC.

If the continuation model is unavailable, the system falls back to fixed-target exit. It never defaults to "hold."

Part A: Direction Lock State Machine
A1. Concept
The system maintains, per symbol, a directional state that gates signals. When the system commits to a level (long break or short break), the opposite side is suppressed until either (a) the commitment fails, (b) time expires, or (c) price validates a reversal through the same level.

Cooldown after failure is tracked per level, not per symbol. A failure at PDH does not prevent the system from later locking on POC. Cooldown suppresses new lock entry only; signals still pass through arbitration. The lock is a filter, not a gate.

A4. Trigger conditions (exact)
Entry conditions (A4.1) are evaluated at signal time. Exit conditions (A4.2) are evaluated at bar close. See A6 for the call graph.

A4.1 Entry into lock (only from NEUTRAL, evaluated at signal time)
For a BUY signal whose entry_price is within LEVEL_PROXIMITY_TICKS × TICK_SIZE of any registered level L:

If the signal bar's close ≥ L + LOCK_CLOSE_BUFFER_TICKS × TICK_SIZE, candidate lock on L.

Else no state change.

For a SELL signal whose entry_price is within LEVEL_PROXIMITY_TICKS × TICK_SIZE of any registered level L:

If the signal bar's close ≤ L − LOCK_CLOSE_BUFFER_TICKS × TICK_SIZE, candidate lock on L.

Else no state change.

If multiple levels qualify:

LOCK_MULTI_LEVEL_MODE = 'nearest': choose the level with smallest |close − L|.

LOCK_MULTI_LEVEL_MODE = 'all': lock on the level with smallest |close − L|, and write the full qualifying set into signal_arbitration.veto_reason for audit.

Before committing the lock, check level_cooldowns for (symbol, level_name). If now < cooldown_until, suppress the lock (state stays NEUTRAL) and log LOCK_SUPPRESSED_COOLDOWN in signal_arbitration. The signal itself is still allowed.

On commit:

text
state = LONG_LOCKED | SHORT_LOCKED
locked_level_name = L
locked_level_price = L
locked_at = signal_ts
lock_bar_count = 0
last_extreme_price = signal bar high (LONG) | low (SHORT)
last_extreme_at = signal_ts
A4.2 Exit from lock (only from LONG_LOCKED or SHORT_LOCKED, evaluated at bar close)
For LONG_LOCKED:

Failure: if bar close ≤ locked_level_price − LOCK_FAILURE_TICKS × TICK_SIZE:

state = NEUTRAL

INSERT INTO level_cooldowns (symbol, level_name, cooldown_until, reason) VALUES (symbol, locked_level_name, now + LOCK_COOLDOWN_BARS * bar_interval, 'FAILURE') ON CONFLICT (symbol, level_name) DO UPDATE SET cooldown_until = EXCLUDED.cooldown_until

Timeout: if lock_bar_count >= LOCK_TIMEOUT_BARS AND (now − last_extreme_at) >= LOCK_STALL_BARS * bar_interval:

state = NEUTRAL

INSERT INTO level_cooldowns (... 'TIMEOUT') as above.

Validation: if bar close ≥ locked_level_price + LOCK_FAILURE_TICKS × TICK_SIZE:

reset lock_bar_count = 0 (lock persists; the level has been confirmed by the same distance that would invalidate it)

Always: if bar high > last_extreme_price:

last_extreme_price = bar high

last_extreme_at = bar_ts

For SHORT_LOCKED: mirror (low, ≤, ≥).

Note on validation: threshold is LOCK_FAILURE_TICKS, symmetric with the failure threshold. The original spec used 2 × LOCK_CLOSE_BUFFER_TICKS, which at defaults (0.50 NQ points) reset on tick noise and defeated the timeout entirely.

A4.3 Cooldown enforcement
While now < level_cooldowns.cooldown_until for a given (symbol, level_name), no new lock may be entered on that level. A qualifying signal at that level during cooldown is logged as LOCK_SUPPRESSED_COOLDOWN in signal_arbitration with allowed = TRUE. The signal proceeds to execution normally.

Cooldown does not affect other levels. Cooldown does not veto signals.

A5. Signal arbitration (exact)
Applied in the signal handler, after meta-labeling filter (if live) and before execution. Also evaluates A4.1 as a side effect (lock entry).

python
def arbitrate(signal, state, now):
    """
    Returns (allowed: bool, veto_reason: str|None, lock_note: str|None).
    lock_note is populated when the signal would have locked but was suppressed
    by cooldown, or when it successfully locked.
    """
    if signal.direction == "BUY" and state.state == "SHORT_LOCKED":
        return False, f"opposite lock: SHORT_LOCKED at {state.locked_level_name}", None
    if signal.direction == "SELL" and state.state == "LONG_LOCKED":
        return False, f"opposite lock: LONG_LOCKED at {state.locked_level_name}", None
    return True, None, None
Cooldown is not checked here. It is checked in A4.1 and results in a lock_note, not a veto.

Same-side signals while locked are allowed.

A6. Call graph (exact)
Two entry points. They are not interchangeable.

A6.1 Bar-close update — POST /arbitrate/update {symbol, bar_ts, close, high, low}
Called on every 1-minute bar close during RTH.

Order:

Insert level_snapshot row for this bar.

Load direction_state for symbol.

If state is NEUTRAL: do nothing.

If state is LONG_LOCKED or SHORT_LOCKED:

evaluate A4.2 (failure, timeout, validation)

update last_extreme_price / last_extreme_at

increment lock_bar_count

Write back to direction_state.

If LOCK_SESSION_BOUNDARY_RESET = 'yes' and bar_ts is at RTH open:

force state = NEUTRAL, clear lock fields.

A6.2 Signal-time check — POST /arbitrate/check {signal_id}
Called from POST /api/signals/fire, after meta-labeling filter.

Order:

Load signal, load direction_state for symbol, load latest level_snapshot.

Evaluate A4.1 (lock entry). May suppress on cooldown or commit a lock.

Evaluate A5 (arbitration).

Write signal_arbitration row (always, allowed or vetoed).

Return {allowed, veto_reason, lock_note}.

A10. Fallback
If direction_state is missing or unreadable, or if level_snapshot is stale (last update > 5 minutes ago during RTH), arbitrate() returns (True, None, None) and lock entry is skipped. Signals pass through unfiltered.

Staleness is determined by a single shared function:

python
def levels_fresh(symbol, now):
    last = query_last_level_snapshot(symbol)
    if last is None: return False
    return (now - last.ts) <= timedelta(minutes=5)
Both A6.1 and A6.2 call levels_fresh(). Do not duplicate the check.

The lock is a filter, not a gate. Never block trading because of an infrastructure failure.

Part B: Continuation Model
B1. Concept
When an open trade reaches TARGET_HIT_R_MULT (default 1R), the continuation model is consulted. It returns P(price will extend CONTINUATION_EXTENSION_R further without retracing CONTINUATION_RETRACE_ABORT_R). This probability drives a three-tier exit decision.

B3. Snapshot trigger
continuation_snapshots rows are created at the moment a live or historical trade reaches TARGET_HIT_R_MULT. In backfill (see B7), run over historical signal_labels where exit_reason = 'TARGET'.

Features are computed from nq_bars and level_snapshot at the snapshot bar. All windows strictly ≤ snapshot_ts.

B4. Feature definitions (exact)
Define R once, at the top of the snapshot builder:

text
R_ticks = abs(target_price - entry_price) / TICK_SIZE
This equals TARGET_HIT_R_MULT * initial_risk_ticks by construction. Do NOT derive R from bar_close_at_target. If the target bar closed past target, close-based R inflates extension and abort thresholds proportionally and silently weakens the label.

All distance values in ticks.

Feature	Formula
r_gained_so_far	(close − entry) / (R_ticks * TICK_SIZE) for BUY; (entry − close) / (R_ticks * TICK_SIZE) for SELL
bars_held	bars since signal timestamp
dist_to_next_level_ticks	For BUY: min over registered levels L > target_price of (L − close) / TICK_SIZE. For SELL: mirror. If no level qualifies, 9999.
next_level_name	name of the level from the above; 'NONE' if none
close_beyond_level_ticks	For BUY: let L be the nearest registered level ≤ close. If L exists: (close − L) / TICK_SIZE. If no L ≤ close: −1 * (nearest L > close − close) / TICK_SIZE, i.e. negative distance to the level still ahead. If no levels at all: −9999. For SELL: mirror.
wick_ratio	For BUY: (high − close) / (high − low) on target bar. For SELL: (close − low) / (high − low). If high == low, 0.
rel_volume_5	sum(volume, 5) / (sum(volume, 20) / 4)
cvd_slope_5	linear regression slope of session-cumulative delta, last 5 bars
cvd_slope_15	same, window 15
bars_since_new_extreme	bars since highest high (BUY) / lowest low (SELL) since signal
range_expansion_ratio	(high − low)_last_bar / mean(high − low, 20)
dist_to_vwap_ticks	(close − vwap) / TICK_SIZE, signed
minutes_since_rth_open	same as meta-labeling spec
minutes_until_rth_close	same as meta-labeling spec
session_range_ticks	(session_high − session_low) / TICK_SIZE
swing_structure_score	see below
swing_structure_score definition (pinned):

A swing high is a bar whose high is strictly greater than the highs of the 2 bars on each side (5-bar fractal). A swing low is symmetric on lows. Confirmed swings are those with 2 bars of right-side confirmation available.

For BUY trades: take the last 3 confirmed swing highs at or before snapshot_ts.

100 if strictly ascending (h1 < h2 < h3)

20 if strictly descending (h1 > h2 > h3)

50 otherwise

For SELL trades: mirror on swing lows.

If fewer than 3 confirmed swings exist, score = 50.

B5. Labeling (exact)
Forward window = CONTINUATION_LOOKAHEAD_BARS bars after snapshot_ts.

python
def label_continuation(snapshot, bars_forward, tick_size):
    direction = snapshot["direction"]
    entry = float(snapshot["entry_price"])
    target = float(snapshot["target_price"])
    close = float(snapshot["bar_close_at_target"])

    # R derived from target_price, not close. See B4.
    R_ticks = abs(target - entry) / tick_size

    ext_ticks = CONTINUATION_EXTENSION_R * R_ticks
    abort_ticks = CONTINUATION_RETRACE_ABORT_R * R_ticks

    if direction == "BUY":
        ext_price = close + ext_ticks * tick_size
        abort_price = close - abort_ticks * tick_size
    else:
        ext_price = close - ext_ticks * tick_size
        abort_price = close + abort_ticks * tick_size

    forward_mfe = 0
    forward_mae = 0
    bars_to_ext = None

    for i, bar in enumerate(bars_forward.iterrows(), start=1):
        ts, b = bar
        if direction == "BUY":
            forward_mfe = max(forward_mfe, (b["high"] - close) / tick_size)
            forward_mae = max(forward_mae, (close - b["low"]) / tick_size)
        else:
            forward_mfe = max(forward_mfe, (close - b["low"]) / tick_size)
            forward_mae = max(forward_mae, (b["high"] - close) / tick_size)

        hit_abort = (
            (direction == "BUY" and b["low"] <= abort_price) or
            (direction == "SELL" and b["high"] >= abort_price)
        )
        hit_ext = (
            (direction == "BUY" and b["high"] >= ext_price) or
            (direction == "SELL" and b["low"] <= ext_price)
        )

        if hit_abort and not hit_ext:
            return {"label": 0, "forward_mfe_r": forward_mfe / R_ticks,
                    "forward_mae_r": forward_mae / R_ticks, "bars_to_extension": None}
        if hit_ext and not hit_abort:
            return {"label": 1, "forward_mfe_r": forward_mfe / R_ticks,
                    "forward_mae_r": forward_mae / R_ticks, "bars_to_extension": i}
        # Same bar hits both -> conservative: label 0 (abort)
        if hit_abort and hit_ext:
            return {"label": 0, "forward_mfe_r": forward_mfe / R_ticks,
                    "forward_mae_r": forward_mae / R_ticks, "bars_to_extension": None}

    # Neither hit within window -> label by net direction
    end_close = float(bars_forward.iloc[-1]["close"])
    if direction == "BUY":
        net_r = (end_close - close) / (R_ticks * tick_size)
    else:
        net_r = (close - end_close) / (R_ticks * tick_size)

    return {"label": 1 if net_r > 0 else 0,
            "forward_mfe_r": forward_mfe / R_ticks,
            "forward_mae_r": forward_mae / R_ticks,
            "bars_to_extension": None}
Tie-break: abort wins. Conservative.

B9. Threshold selection
Three-band decision. Default bands:

HOLD_THRESHOLD = 0.65 — P ≥ 0.65 → hold full runner

SCALE_THRESHOLD = 0.45 — 0.45 ≤ P < 0.65 → scale half, trail half

EXIT_THRESHOLD = 0.45 — P < 0.45 → exit at target

Tune HOLD_THRESHOLD and SCALE_THRESHOLD on the CV folds by maximizing:

text
E[value | decision] = P(extend | p in band) * avg_extension_ticks
                    - P(retrace | p in band) * avg_retrace_ticks
subject to: each band contains ≥ 40 samples in CV test folds.

B10. Production application
Called only when an open trade reaches TARGET_HIT_R_MULT. Sequence:

Compute snapshot at the target-hit bar (Section B4).

Send features to /predict/continuation on the microservice.

Receive P(extend).

Apply band:

javascript
if (p >= HOLD_THRESHOLD) {
    // Move stop to breakeven. No fixed target. Trail on full remaining size.
    // Trail mechanism per RUNNER_TRAIL_TYPE.
    // Log decision HOLD_RUNNER.
} else if (p >= SCALE_THRESHOLD) {
    // Book 50% at target. Move stop to breakeven on remainder.
    // Apply trail per RUNNER_TRAIL_TYPE.
    // Log decision SCALE_AND_TRAIL.
} else {
    // Exit at target. Log decision EXIT_AT_TARGET.
}
If the microservice is unavailable, fall back to EXIT_AT_TARGET. Never fall back to hold.

C2. Bar-close hook
Express must call /arbitrate/update on every 1-minute bar close during RTH (09:30–16:00 ET). Simplest: a cron firing every minute at :00 seconds that reads the latest nq_bars row and posts it. If the bar is missing (data lag), log and skip; the state machine tolerates gaps up to 5 minutes before it forces NEUTRAL. See A10.

C3. Signal handler order (final)
In POST /api/signals/fire:

Insert raw_signals row (existing).

Call meta-labeling /snapshot (if spec implemented).

Call meta-labeling /predict (if live).

Call /arbitrate/check.

If any filter vetoes, update raw_signals.status and return.

Otherwise execute.

On trade close, if exit_reason would have been TARGET at TARGET_HIT_R_MULT, call /snapshot/continuation and /predict/continuation to determine the actual exit action.

Part D: Deployment Order
Implement Part A (direction lock). Test. Deploy in log_only mode first — arbitration runs, logs decisions, but does not veto.

Run log-only for 7 days. Review signal_arbitration: how many signals would have been vetoed? Are they correct? Inspect lock_note distribution.

Flip arbitration to enforce. Monitor for 7 days.

Implement Part B snapshots and backfill. Verify ≥ 500 labeled snapshots.

Train continuation model. Evaluate on held-out test.

Deploy in log_only mode — predictions logged, exits unchanged.

Review 14 days of decisions. Confirm HOLD decisions correlate with larger realized PnL.

Flip to enforce. Monitor for 14 days.

Install retrain cron for continuation model (cadence per CONT_THRESHOLD_CADENCE).

Part E: What Success Looks Like
Part A:

Opposite-side signals at levels drop by 70%+.

Same-side continuation signals are unaffected.

LOCK_SUPPRESSED_COOLDOWN rate is low (< 10% of qualifying signals). If high, cooldown is firing too aggressively or levels are too close together.

The proportion of days with whipsawing entries at the same level drops.

Part B:

Trades tagged HOLD have higher average MFE than trades tagged EXIT.

Realized PnL on HOLD trades exceeds what fixed-target would have produced.

Realized PnL on EXIT trades is roughly equal to fixed-target.

Home-run count (trades ≥ 3R) increases without an increase in average loss.

If after 30 days live neither pattern holds, the model is not adding value. Roll back per Section F.
