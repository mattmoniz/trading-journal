# CLAUDE.md

Trading journal: React frontend (Vite, port 3000) + Express backend (port 3002) + PostgreSQL (`trading_journal` db). See [ARCHITECTURE.md](ARCHITECTURE.md) for full route/service/table inventory — this file is conventions and rules, not structure.

**Start of session / after a context clear: read [docs/OPEN_THREADS.md](docs/OPEN_THREADS.md) first.** It tracks unfinished work, unconfirmed proposals, and stale-stats findings from prior sessions — the goal is to never lose a thread to a context reset.

> **CLAUDE.md is an INDEX (cap 40 KB / 300 lines, test_invariants [14]).** Each line below is the rule in brief; the full verbatim text, incident history and numbers are in `docs/CLAUDE_MD_ARCHIVE/` (arrow links). New rules: add a one-line entry here and the full text in the archive file, never a paragraph here.

## Dev workflow

- Start: `./start.sh` (kills stale processes, starts server + client, self-heals the `pre-commit` hook symlink) — Stop: `./stop.sh` or `fuser -k 3002/tcp` — Restart: `./restart.sh` (thin wrapper around `start.sh`, not a separate implementation)
- **Single-instance server takeover lives in ONE place: `scripts/lib/server-lifecycle.sh`**, sourced by `start.sh`, `restart.sh`, `stop.sh` and `scripts/dev-server-guard.sh` (what `npm run server` runs). Never reimplement any piece of it in a new entry point; source the shared lib. [→](docs/CLAUDE_MD_ARCHIVE/dev_workflow.md#dw-001)
- `git commit` runs a **pre-commit hook** (`scripts/git-hooks/pre-commit`, symlinked from `.git/hooks/pre-commit` — `.git/hooks/` isn't tracked, `./start.sh` re-creates the symlink if missing) that blocks new hardcoded trading-threshold anti-patterns in `acd.js`/`caseEngine.js`, plus 3 more broadly-scoped patterns across `server/`/`src/`/`scripts/` (wrong $/pt constants, `SUM(pnl)`-style CumPL-diff violations, the JS-`toISOString()`-for-a-trading-day-date bug) — 7 patterns total, defined once in `scripts/hardcoded-threshold-patterns.sh` and shared with the Stop hook's advisory version. Deliberate exception: `ALLOW_HARDCODED=1 git commit ...`.
- Server only: `npm run server` (now `scripts/dev-server-guard.sh` — stops systemd, kills any stale nodemon/node instance, hands the port back on exit; no longer a bare `nodemon` with no cleanup) — Client only: `npm run client`
- DB: `server/schema.sql` is a full `pg_dump --schema-only` snapshot (122 tables/views, regenerated 2026-06-30 after a dead-table cleanup) — there's still no tracked migration history, so it drifts again the moment a table is added/altered live without regenerating. See the regen command in [ARCHITECTURE.md](ARCHITECTURE.md#schema-source-of-truth). When in doubt, query `information_schema.tables`/`information_schema.columns` against the live DB rather than trusting the file is current.

## Documentation maintenance — keep this perpetually current

This file and [ARCHITECTURE.md](ARCHITECTURE.md) are the handoff point for the next session (human or Claude) — treat letting them go stale as a real cost, the same as introducing a bug. A `Stop` hook (`.claude/settings.json`) checks at the end of every session whether structural files changed without a matching doc update and prints a reminder — if you see that reminder, act on it before ending the turn rather than dismissing it.

Concretely, whenever a session does any of the following, update the relevant doc **in that same session**, not as a follow-up:
- Add/remove a route file, service file, or DB table → update [ARCHITECTURE.md](ARCHITECTURE.md)'s route/service/table tables, and if a table was added/dropped/altered, regenerate `server/schema.sql` (command is in ARCHITECTURE.md)
- Add/remove a dashboard component → update the frontend structure table in [ARCHITECTURE.md](ARCHITECTURE.md)
- Establish a new hard rule or convention (the user corrects an approach, or confirms a non-obvious one) → add ONE line (≤ 200 chars) with `python3 scripts/claude_md_add_rule.py <hard_rules|conventions|collaboration> "<line>" --full <file>`; the full text goes to `docs/CLAUDE_MD_ARCHIVE/`, never a paragraph here (pre-commit blocks > 40 KB / 300 lines, override `ALLOW_CLAUDE_MD_GROWTH=1` with a stated reason)
- A research result, incident narrative or number is NOT a CLAUDE.md entry: record it via `scripts/record_claim.mjs`, `scripts/flag_decision.mjs` or `docs/OPEN_THREADS.md`; add a one-line pointer here only if a future session must know where to look
- Fix something listed in [docs/KNOWN_ISSUES.md](docs/KNOWN_ISSUES.md) → remove that entry; discover a new one → add it
- The user confirms a fix/decision but it isn't fully implemented in the same session, proposes a follow-up that isn't confirmed yet, or you find a stat/display that's stale or disconnected from its source of truth → add it to [docs/OPEN_THREADS.md](docs/OPEN_THREADS.md) **before the session ends** — don't rely on conversation memory alone to carry pending work forward. This is on you to maintain proactively; the user has delegated it rather than asking for it each time.
- `docs/` also holds point-in-time specs (`MONTE_CARLO_SPEC*.md`, `BACKTESTING_PLAYBOOK.md`) and parked design docs (`*_parked.md`) — those describe proposals, not live state, and aren't required to track the running app. Don't confuse them with ARCHITECTURE.md.
- **Any change that supersedes existing code, data, or documentation must clean up what it replaces in the same session** — don't leave stale duplicate descriptions, dead constants/variables, orphaned scratch/temp files, or superseded DB rows sitting alongside the replacement. Concretely: rewriting a script's methodology → grep for every other doc that describes the old methodology (not just the primary one) and update all of them, and remove now-unused constants/params from the code itself; reverting a bad live change → delete the temp files used to make and revert it; a finding that invalidates an old proposal → replace/remove the old note, don't just append a new one next to it (OPEN_THREADS.md especially — resolved items get struck through with a "Resolved <date>" note per its own convention, not left dangling as if still open; see that file's own header — the older "delete when fixed" wording was changed 2026-07-14). Restated 2026-07-13 after a session left stale/duplicate descriptions in ARCHITECTURE.md and HARDCODED_CONSTANTS.md that had to be caught separately after the code change was already done.

There is exactly one canonical architecture doc — `/ARCHITECTURE.md` at the repo root. If you're ever tempted to write a second one (e.g. inside `docs/`), update the existing one instead; a prior session already made that mistake once (`docs/ARCHITECTURE_2026-06-07_superseded.md`) and it silently went stale because nothing pointed back to it.
