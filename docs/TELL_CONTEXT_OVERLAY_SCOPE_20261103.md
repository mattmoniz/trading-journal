## 3. Design
Phase 1 (read-only, nothing live changes):
- CONTEXT OVERLAY at every tell fire, computed causally from the same completed bars: location in the RTH value area (VAL..VAH), POC, day shape (balanced or breaking out), nearest relative LVN (side, depth at that moment), Globex/RTH value relation, defended-level flag (once the user defines it), and a label AGREES / AGAINST / NEUTRAL against the tell's direction (thirds of value, a convention, shown as NOT VALIDATED). Persisted append-only in its own table keyed by `amt_tell_trades.id` (hr-068), shown on the tell chart and as ONE section of the Monitor & Learning page (cv-110), never in `acd.js`.
- SHADOW CONTEXT BOOKS, logged with simulated fills, one-position rule, entry price identical to the tell's: A = tell V1 as is (baseline); B = direction from context (flip on AGAINST, optional skip on NEUTRAL); C = management from context (stop tucked beyond the last defended level when balanced and at the edge; wide stop and hold when breakout is likely). Every comparison needs an entry-price-only control arm (hr-042) and the same exit (cv-026). Forward scorecard, fixed review cadence.
- "Learns and adapts" = forward log + fixed-schedule review with a pre-declared promotion gate (champion/challenger, no daily peeking, no optional stopping, cv-006), no hardcoded thresholds (hr-003); never auto-tunes on single trades.
Phase 2 (only on the user's go, own design critique and code review, hr-031): the context book trades on the sim account through the EXISTING order path (an `active_setups` row, no new order code, cv-078). It replaces the tell's orders on that account (one position at a time; broker aggregate cannot be split by book, hr-066), which pauses the clean Stage 2 count (the user decided 2026-11-01 to leave it unchanged until about 150 trades). A restart disarms the Sierra switch (cv-102); re-arm is the user's call. In Sierra the orders, fills and stop show like the tell's do today; there is no known way to draw on the Sierra chart (not investigated; hr-027).
