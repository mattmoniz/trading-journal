# CLAUDE.md

Trading journal: React frontend (Vite, port 3000) + Express backend (port 3002) + PostgreSQL (`trading_journal` db). See [ARCHITECTURE.md](ARCHITECTURE.md) for full route/service/table inventory — this file is conventions and rules, not structure.

**Start of session / after a context clear: read [docs/OPEN_THREADS.md](docs/OPEN_THREADS.md) first.** It tracks unfinished work, unconfirmed proposals, and stale-stats findings from prior sessions — the goal is to never lose a thread to a context reset.

> **CLAUDE.md is an INDEX (cap 40 KB / 300 lines, test_invariants [14]).** Each line below is the rule in brief, ending with its entry id; the full verbatim text, incident history and numbers are in `docs/CLAUDE_MD_ARCHIVE/` (path under each heading). New rules: add a one-line entry here and the full text in the archive file, never a paragraph here.

## Dev workflow

- Start `./start.sh` (kills stale processes, starts server + client, re-creates the `pre-commit` hook symlink); stop `./stop.sh` or `fuser -k 3002/tcp`; restart `./restart.sh` (wrapper around `start.sh`).
- Single-instance server takeover lives ONLY in `scripts/lib/server-lifecycle.sh`, sourced by `start.sh`, `restart.sh`, `stop.sh` and `scripts/dev-server-guard.sh`; never reimplement it in a new entry point. (dw-001)
- `git commit` runs `scripts/git-hooks/pre-commit` (symlinked from `.git/hooks/`), which blocks 7 hardcoded-threshold anti-patterns defined once in `scripts/hardcoded-threshold-patterns.sh` (shared with the Stop hook) and the CLAUDE.md size cap. Deliberate exception: `ALLOW_HARDCODED=1 git commit ...`.
- Server only `npm run server` (`scripts/dev-server-guard.sh`: stops systemd, kills stale nodemon/node, hands the port back on exit); client only `npm run client`.
- DB: `server/schema.sql` is a `pg_dump --schema-only` snapshot (regen command in [ARCHITECTURE.md](ARCHITECTURE.md#schema-source-of-truth)); there is no migration history, so it drifts when a table changes live without regenerating. When in doubt query `information_schema` on the live DB.

## Hard rules

Full text of each entry: `docs/CLAUDE_MD_ARCHIVE/hard_rules.md`, anchor = the id in parentheses (also greppable as `<a id="ID">`).

- No dead ends: every decision-driving signal must be persisted queryably, rechecked on a schedule, wired to a consumer (or flagged), and discoverable. (hr-001)
- Evaluate every new setup/signal for BOTH RTH and Globex before calling it done; a recorded 'doesn't apply overnight' is fine, an untested gap is not. (hr-002)
- No static thresholds: derive every cutoff from a rolling distribution; dated backtest comments with no scheduled recalibration are standing audit targets. (hr-003)
- P&L uses the CumPL diff method scoped to `account LIKE '%-PRO%'`, never `SUM(pnl)`/`SUM(FlatToFlat)`; keep `/api/daily-logs` and `/api/stats/daily` in sync. (hr-004)
- Trades are MNQ: $2/point, $2 round trip (ground truth `server/config/instruments.js`); never copy a $/pt or commission constant without checking it. (hr-005)
- ~80% of `active_setups` is synthetic BACKFILL: filter `origin_status` (ACTIVE/SHADOW are real) before presenting any figure as realized performance. (hr-006)
- Real-N/EV queries over `active_setups` also need `is_cluster_primary` (cluster siblings double count), in backend AND frontend sums. (hr-007)
- Never fabricate a stat: a win-rate claim needs N>=20 to be called decisive; below that say so explicitly. (hr-008)
- `performance_audit` queries by `signal_type` need `DISTINCT ON (...) ORDER BY ..., run_date DESC, id DESC`, with value filters applied AFTER the dedup. (hr-009)
- Before blaming a refactor for a byte-diff, call the same post-refactor code twice; a live endpoint can differ on its own (drift or non-determinism). (hr-010)
- A backtest-reference script needs its own `signal_type`, never SETUP_STATUS/OPTIMAL_STOP under the real pipeline's `signal_name` (values alternate silently). (hr-011)
- `REAL_TRADE_FILTER` drops MARK_TO_MARKET, undercounting real wins of timeout-exit setups; check the resolution_method mix before trusting THIN_N. (hr-012)
- Standalone detectors' in-memory poll-skip caches can insert a real signal hours late after a restart; the row is timestamped correctly, so check `late_backfill_min`. (hr-013)
- `price_bars_primary`'s live branch can silently return stale prices (root cause still open); never trust a 'current price' without a freshness check. (hr-014)
- WSL2 to the Windows host: use the NAT gateway IP (`ip route show | grep default`), not the LAN IP, which connects then resets once data flows. (hr-015)
- This is WSL2 on a machine that sleeps: sleep is a FULL outage with no app-log trace; look for a Started with no Stopped and check `dmesg -T`/`uptime`. (hr-016)
- After any backgrounded `./restart.sh`/`./start.sh`, verify exactly ONE `node server/index.js` with `ps -ef` (not `pgrep -f`); run `./stop.sh` if there are two. (hr-017)
- Which Sierra instance exports fresh bars depends on which has the active chart; ask the user before flipping `SIERRA_DATA_PATH`; the freshness alert catches a stale feed. (hr-018)
- Never hand-type a WR%/N/$ literal into a live-rendered card or label; derive it from a fetched `performance_audit` row or a backtest script. (hr-019)
- No lookahead: backtests, replays and the case engine may use only information available at that point in time. (hr-020)
- Volume profiles (POC/VAH/VAL) must spread each bar's volume across its high-low range; use `computeProfile()`/`computeVolumeProfileForRange()`. (hr-021)
- Export and reuse the real function; never re-implement live-derived classification logic in a backtest script (two copies disagree). (hr-022)
- Every script that reads outcome labels logs a look in the ledger (`research_looks`) first; spend a sealed hold-out only via `spendSealedLook()`. (hr-023)
- Record every tested claim (positive or negative) via `recordClaim()`; never hand-write the INSERT. (hr-024)
- A claim's `next_recheck_due` is only a flag; wire open findings' scripts into the weekly/daily job or they never recompute. (hr-025)
- Resolve every `isolation: worktree` agent dispatch (merge or discard) before the session ends; never leave one to be found later. (hr-026)
- Do not guess third-party tool behavior (especially Sierra Chart); fetch the documentation or ask. (hr-027)
- Process large files and tables in chunks or streams (a 1 GB .scid in memory killed a run and froze WSL); filter by date first. (hr-028)
- Never write a file over 400 lines in one Write call; Write the first section, then append with `cat >>`. (hr-029)
- Use Gemini for DB mining and pattern analysis, Claude for implementation and for interpreting results. (hr-030)
- Higher-stakes or live-wiring work gets three phases: design critique, the analysis, then a review-only pass before shipping. (hr-031)
- Default for research: Gemini/DeepSeek critique the idea, mine, and review code; Claude audits every output and decides. (hr-032)
- Gemini gets two correction attempts on wrong output; after the second wrong answer Claude does the task directly. (hr-033)
- Audit all Gemini output: re-query 3-5 key claims directly (100%/0% WR, day clustering, grid baseline, N counts) before acting. (hr-034)
- A reviewer's correct diagnosis does not oblige its recommended remedy: take the diagnosis, apply the house convention, document the deviation. (hr-035)
- Record pending decisions with `flag_decision.mjs`, not prose; resolve ones your own work answers; read `notes.status`, not the narrative. (hr-036)
- A code comment saying a number was 'verified' is not verification; re-check it before depending on the value. (hr-037)
- `computeRigor()`'s tercile 'stable' check can mislead on thin, day-correlated data; prefer `dayBlockedBootstrapCI()` when a finding matters. (hr-038)
- Assume RTH-validated 'momentum/flow against the fade' signals REVERSE in Globex; test Globex from scratch, never loosen RTH numbers. (hr-039)
- If you add a smarter computation over a stored field, rewire or rename that field and add an invariant re-deriving it with the real function. (hr-040)
- A comparison is only as trustworthy as its least-audited side: compute the baseline with the same method, in the same pass, as the candidate. (hr-041)
- Two arms with different entries and a shared exit need an entry-price-only control arm before crediting the 'smarter' arm. (hr-042)
- When tightened guardrails are re-run, explicitly delete the old `performance_audit` rows that no longer survive; ON CONFLICT alone won't. (hr-043)
- A candidate grid needs a floor from the data's own resolution; finer-than-resolvable candidates pass statistical guardrails by construction. (hr-044)
- The grid's 'best' cell needs its own day-cluster, mean/median and chronological check at its exact population and simulation. (hr-045)
- A catch-rate from a loose time-window match can be a matching artifact when the strategy stops out or resolves faster than the window. (hr-046)
- Verify a fix by which code branch actually ran, not a pooled before/after average (a fallback branch can hide behind it). (hr-047)
- A `curl localhost:3002` check proves a fix only if the server restarted since the edit; check `ps -p <pid> -o etime` first. (hr-048)
- Before calling a frontend change done run `npm run lint:frontend` and `npm run build`, and check `[CLIENT_ERROR]` entries. (hr-049)
- Before auditing a component, `grep` its mounts and trace prop-gated branches: fixing unreachable code fools reviewer and fixer. (hr-050)
- Data-fetching changes need measured load performance (request count, settle time, `curl` timing), not just no errors. (hr-051)
- Before building or exploring, `grep ARCHITECTURE.md` for the capability; it is more complete than assumed. (hr-052)
- A statistically real split does not validate the classifier that made it; validate a new classifier's parameter robustness first. (hr-053)
- Bar-derived tables (`level_prices`, `developing_value_log`, `acd_daily_log`) go stale silently; re-derive and run the audits after any bar repair. (hr-054)
- A PENDING `OPEN_DECISION` was true when last checked; verify its claim before relying on it, especially for files it names. (hr-055)
- A pre-compaction 'confirmed' claim is not evidence; redo the check on current data before resolving anything on it. (hr-056)
- Test market-behavior hypotheses on raw bar history first; use `active_setups` only to ask how this system's own setups perform. (hr-057)
- A new endpoint called from `server/public/*.html` is not done until its exact path is in `~/.cloudflared/config.yml` (302 on the tunnel, not 404). (hr-058)
- A frontend `row.field !== literal` filter becomes a silent no-op if the backend stops returning `field`; grep consumers when editing a SELECT. (hr-059)
- In `main().then(() => process.exit(0))` scripts `await` every async call, or exit races and drops work while the log claims success. (hr-060)
- 2026-10-11/12 is a confound boundary: never judge or revert a mechanism with data crossing it; report POC join separately. (hr-061)
- Don't use a day-weighted CI point estimate as '$/trade' to compare split subgroups; report sum(pnl)/N and day-block only the CI. (hr-062)
- A pooled window is confounded if the live system itself changed in it (roster growth, overrides); check the setup roster per week. (hr-063)
- A later force-SHADOW/pause override silently wins over earlier ones; before adding one, read every other override and their order. (hr-064)
- Before a 'promote regardless' simplification, re-read the override's documented exclusions; gate on independent flags, not a collapsed reason string. (hr-065)
- A broker aggregate (account position) can't be attributed to one strategy; use it only as a fail-closed cross-check, never as an oracle. (hr-066)
- Never apply async status updates last-write-wins: terminal states (FILLED) are absorbing and monotonic fields only increase. (hr-067)
- Keep the full event history (append-only log) for any state derived from an external event stream; a last-message column can't be repaired later. (hr-068)
- A strict 'unknown broker order' halt is only usable on an account kept free of unrelated resting orders; clear clutter in Sierra, don't soften the halt. (hr-069)

## Conventions

Full text of each entry: `docs/CLAUDE_MD_ARCHIVE/conventions.md`, anchor = the id in parentheses (also greppable as `<a id="ID">`).

- A real row resting on a basis live wouldn't accept (stale price, fill past order expiry) gets a `*_basis` boolean excluded in REAL_TRADE_FILTER; never delete the row. (cv-001)
- R-multiple (MFE/risk) only means something when stop and target are a calibrated pair (e.g. OPTIMAL_STOP); meaningless when each is anchored to its own structural level. (cv-002)
- Two resolvers on different timers race at the same expiry; a setup with its own exit branch in `resolveSetupsByPrice()` must be excluded from the `expireStaleSetups()` backstop for a grace window. (cv-003)
- A `setup_type` without `_OVERNIGHT` is not guaranteed RTH-only (e.g. PD_VAH fires in both); split by the `is_rth` column. (cv-004)
- When matching a real event to a bar-derived level touch, record every touch episode in a session, not just the first. (cv-005)
- A script that retrains on a sliding window and re-checks significance daily is optional stopping, even if each check is honest. (cv-006)
- A shuffle-to-break-signal leakage control must use the same real features on fit and predict; prefer the repo's day-block LABEL permutation over a feature shuffle. (cv-007)
- A localStorage drag-reorder column order must be MERGED with the current column set at load (new columns appended), never just filtered against it. (cv-008)
- Any `price_bars_primary` query (a non-indexable VIEW) needs BOTH bounds; lower-bound-only `ts >= X` and upper-bound-only `ts < X` each force a full aggregation. (cv-009)
- Never look up a bar by exact timestamp match against a real trade's `fired_at` (sub-minute vs on-the-minute bars); floor to the minute or the trade is silently dropped. (cv-010)
- `ts < date_trunc('minute', NOW())` can silently read the previous bar in a new minute's first seconds (ingestion lag, ~1/3 of fires land in that window); no flag shows it. (cv-011)
- Comparing a `NOW()` string to a naive timestamp column needs `::timestamp` before `::text`; `NOW()::text` carries a UTC offset suffix so raw string equality fails. (cv-012)
- WEEKLY_VWAP covers all sessions from Sunday 18:00 ET through the start of the row's session; MONTHLY_VWAP from 00:00 ET on the 1st. Check the definition before comparing to a chart. (cv-013)
- Never shift dates by months with `setUTCMonth(getUTCMonth() - n)` (silent overflow); use `shiftMonthsClamped()` in `server/lib/dateMath.js`. (cv-014)
- A `level_prices` prior-day lookup with `<=`/`DESC` goes an extra session stale across a 2+ day closure; search `>=`/`ASC` for the nearest following checkpoint. (cv-015)
- 'Latest date with any bars, then filter to RTH hours' returns NULL (no error) on the first day after a 2+ day closure; pick the date from RTH bars themselves. (cv-016)
- `status` (open lifecycle) and `origin_status` (provenance) both use the string SHADOW for unrelated things; never mix them in a filter. (cv-017)
- A bare Python None in a single-row DataFrame gives dtype=object and LightGBM rejects it; batch runs hide this. Use float NaN for missing numerics when scoring one row. (cv-018)
- An OVERNIGHT level-fade's MFE/MAE (and 'left on the table' stats) can be mostly an untradeable gap; check for a gap-through before trusting them. (cv-019)
- A number computed twice by the same script is not verified; re-derive it independently by another method or by Gemini without showing it the original method. (cv-020)
- Two runs hours apart over a live window with no upper bound are not comparable (the population grew); pin an end date before comparing. (cv-021)
- A simulation target set to a statistic of the SAME population's own MFE (its median etc.) makes the win rate a tautology, not a finding. (cv-022)
- Never key per-trade state by `fired_at`; 12.6% of real trades share an exact timestamp with a cluster sibling. Key by row id. (cv-023)
- A 'find the prior row of this kind' lookup must exclude the current row by its own `id`, not by timestamp or ordering alone. (cv-024)
- A day-blocked bootstrap CI needs correlated confluence-cluster siblings collapsed to one event BEFORE resampling; `is_cluster_primary` dedup for N/P&L doesn't fix it. (cv-025)
- Comparison backtest checklist: confirm the two arms differ only in the hypothesis variable and rule out the other listed confounds before promoting 'A beats B'. (cv-026)
- A containment check against a value derived from the same window is a tautology that can never fail; test against an independent reference. (cv-027)
- A sigma threshold's denominator must be sampled at the same frequency as the live reading (a once-a-day std understates dispersion and makes ordinary readings look extreme). (cv-028)
- A backtest with asymmetric stop/target and a long or no time limit needs a placebo (randomised direction, same structure) before trusting any win rate. (cv-029)
- A stop that takes effect when the market is already beyond it fills at the market (that bar's open), never at the stop price; matters for armed/breakeven stops. (cv-030)
- A research script feeding a live detector must pass the same inputs the live poller does, and its events must be checked for overlap with real live rows. (cv-031)
- Never pass text containing a literal `$` through `node -e "..."` or any double-quoted shell string (`$1` is eaten by bash); write a file and run that. (cv-032)
- A pooled verdict, positive or negative, is a question: split by the natural structural variable (mode, family, session) before trusting it or killing the idea. (cv-033)
- A negative verdict on a runner/winner-extension finding must cite a specific tested mechanism failure with a number, not analogy to another pipeline. (cv-034)
- A runner test that can realize less than the trade's banked outcome tests 'gamble the win'; a floor-preserving variant (stop snaps to the secured level) is a separate test. (cv-035)
- When writing a 'corrected' backtest, diff its candidate-selection logic line by line against the original; a rewrite can silently drop a filter the original had. (cv-036)
- A two-part shadow tracker (inline + completion pass) copied from a sibling must start its completion bar-walk where the NEW step function's semantics begin, not where the sibling's did. (cv-037)
- Benchmarking bundle size across git worktrees: never symlink `node_modules`; the shared `.vite` cache can contaminate another commit's build output. (cv-038)
- A percentile bucket boundary (`pct >= t` vs `pct >= t && pct < 1.0`) can split one bucket into two different subpopulations when the reference sample is small. (cv-039)
- Verify a rebuilt derived table against the convention its source code really uses, not the one you assume (33 of 40 dates looked wrong in `level_prices` but were correct). (cv-040)
- Repairing raw bars means rebuilding every downstream table and flagging every row that consumed them (bad NQ bars reached 4 tables and 1,333 BACKFILL rows). (cv-041)
- An open cluster sibling is not a position until its own resting entry has traded; don't show or count its open P&L before a fill. (cv-042)
- Frontend API calls go straight to the backend via the one `API_URL` constant in `src/constants/api.js` (:3002), never the relative `/api` Vite proxy; don't redeclare it locally. (cv-043)
- Day-stable backend queries (bounded `< date` or otherwise fixed for the day) go through `server/lib/cache.js` `cacheGet`/`cacheSet`, not recomputed per poll. (cv-044)
- `useSharedPollData` dedupes the poll interval, not independently added consumers of a new URL; grep the exact URL for existing consumers before wiring one. (cv-045)
- An expensive endpoint that is polled often or fetched by several components on mount needs a request-coalescing lock, not just a data cache. (cv-046)
- Views stay mounted across tab switches (`visitedViews` + `display:none`); never reintroduce conditional unmount, and gate any polling effect in a view on visibility. (cv-047)
- Every `fetch()` in `quick-check.html` must pass `{ cache: 'no-store' }`; mobile Safari via the Cloudflare tunnel can serve an ETag-cached response on a live dashboard. (cv-048)
- A `quick-check.html` display filter that can hide rows must not persist in localStorage; default to the least-restrictive `'all'` on every load. (cv-049)
- A document-level bubble-phase listener's `stopPropagation()` cannot stop an ANCESTOR's own `onclick`; bubbling reaches the ancestor first. (cv-050)
- Analyses over `active_setups` from 2026-07-09 to 2026-09-16 must exclude rows fired 16:00-18:00 ET (~1,184 post-close flood rows) before trusting counts or means. (cv-051)
- Don't keep adding to `App.jsx`; put new UI in `src/components/dashboard/` or `src/views/`, and shared constants/helpers in `src/constants/` or `src/utils/`. (cv-052)
- New `acd.js` logic goes to `server/services/`, not inline (user directive 2026-09-05 after acd.js crept past 14,000 lines). (cv-053)
- Monolith files get an automatic non-blocking nudge (`.claude/hooks/post-edit-filesize.sh`, median+MAD against sibling files), not a fixed line limit. (cv-054)
- WEEKLY_OPEN no-trade window: `detectGlobexSetup()` nulls `WEEKLY_OPEN` from Sunday 6PM ET level-set until Monday 9:30AM ET RTH open (user rule 2026-09-08). (cv-055)
- Globex no-trade-at-open window: `detectGlobexSetup()` returns null for the first 30 minutes (6:00-6:29:59 PM ET) after the 6PM open, every day. (cv-056)
- RTH-open dead zone 9:30:00-9:34:59 ET: `isInRthOpenDeadZone()` (`acdShared.js`) blocks new entries (user directive 2026-09-25; those fires were -$20 to -$34/trade). (cv-057)

- Server-autonomous detection: `server/index.js` polls `/api/acd/setup-detection` every 15s across the full Globex week (excluding the 5-6PM ET gap), independent of any open browser. (cv-059)
- Level fade detection gate in `acd.js` is `allRthBarsRow.rows.length >= 3` (not 60); IB-specific levels self-gate via `etMinNow >= 630`; don't restore the 60-bar gate. (cv-060)
- `sizeMultiplier` is an IIFE inside `levelScalpSetup` in `acd.js`; a new factor needs N>=20 research, an entry in the IIFE, `AlphaEngineOverview.jsx` updated, and a note in OPEN_THREADS. (cv-061)
- DAY_TYPE_MANAGED types (IB_BULLISH/IB_BEARISH) staying off SUPPRESS may rest on one borderline bucket; re-read the bucket breakdown, not the headline recommendation. (cv-062)
- The trade-brief block later overwrites `active.sizeMultiplier` (post-loss protection), clobbering the level-fade IIFE's ~20-factor value; check the order before adding a sizing factor. (cv-063)
- `sizeMultiplier` (0.10-1.5x) turned into a contract count needs a real floor at zero, not `Math.max(1, ...)`; the user trades exactly 1 MNQ. (cv-064)
- New setup checklist (also for auditing live ones): run `backtest_setup_status.mjs` + `update_optimal_stops.mjs`; N<20 means SHADOW only; no literal stop/target/WR in `acd.js`; more steps in archive. (cv-065)
- `existingSetup` only stops two simultaneously OPEN rows; the unique index `idx_as_unique_touch_instant` blocks re-inserting the same touch instant after the first resolves. (cv-066)
- `backtest_unified.js` `detectLevelFades()` used a blanket 10:30-noon window that doesn't match live (first touch 9:34AM-4PM); only same-day-forming levels keep it, and walk-forward checks were added. (cv-067)
- A `backtest_unified.js` detector matching live's trigger and geometry can still differ (even in sign) from real SETUP_STATUS; check `acd.js` priority-selection candidates before blaming it on a bug. (cv-068)
- Any path that terminally closes an `active_setups` row must compute a real `actual_pnl` in the same transaction; don't rely on a separate expiry job to fix it. (cv-069)
- A record whose entry price differs from its trigger price needs an explicit did-it-fill check before scoring; stop/target checks alone let price jump past both. (cv-070)
- A string written to a short VARCHAR(N) column (`resolution_method` 20, `status` 10, `origin_status` 12, `signal_type` 30) must fit; an overflow throws and crashes the whole poll's row loop. (cv-071)
- A hardcoded `SHADOW_SETUP_TYPES`-style list is the same anti-pattern as a hardcoded suppression list; read `getShadowSetupTypes()` (fresh `performance_audit` query) instead. (cv-072)

- Rigor diagnostics are standing: day-clustering (top-5-dates % of N) plus 3-way chronological sign stability run weekly in all 4 pipelines; informational, they do not feed SUPPRESS/PROMOTE. (cv-075)

- A classifier inferring from `setup_type` NAME alone is wrong when two code paths insert the same name in different contexts (RTH vs Globex); give distinct names or have the producer assert it. (cv-083)
