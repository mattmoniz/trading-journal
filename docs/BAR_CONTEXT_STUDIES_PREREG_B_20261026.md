# Bar-level context studies — Part B: multi-timeframe trend at level touches (pre-registration, 2026-10-25)

Scope: `docs/NEXT_STEPS_SCOREBOARD_AND_BAR_STUDIES_SCOPE_20261025.md` Part 2-B. Part A: `docs/BAR_CONTEXT_STUDIES_PREREG_A_20261026.md` (its lessons apply: print state counts before any outcome, use conditional-minus-unconditional excess, check shared denominators, report opposite-signed subgroups). Committed BEFORE any outcome is computed. Nothing here changes live behaviour. Standing instruction from the user (2026-10-25): "if it's good then implement it" — a result that passes this pre-registered bar AND improves real fills is implemented, observation-only (SHADOW tag) first unless the user says otherwise.

## Question
The user reads fades against higher-timeframe trend (15, 60, 240 bars, the prior session). The 40-moment rating pilot could not test this (charts omitted the higher timeframes). Does the higher-timeframe direction, relative to the fade direction, separate better fades from worse ones? Prior art to respect (read before building anything): `isTrendCounterFade()`, DirGate (`direction_gate_shadow`), MomFade (`momentum_against_fade_shadow`), the CLAUDE.md note that RTH "momentum against the fade" signals reversed in Globex, `rotation_65pt_gate_shadow`. The design must say what is NEW relative to them.

## Population
- **RTH arm (depth):** the 3.5-year roster replay events, `scratch/rotation_gate_replay_rows_ts_20261020.json` (21,480 events 2023-04..2026-10, produced by `scripts/study_rotation_gate_roster_replay_20261020.mjs` / `study_roster_replay_20261019.mjs`: first bar within 15 pt of a live level, once per level per day, direction from the 5-bar approach, calibrated stop/target, simulated P&L, $2/pt, $2 round trip). Each event has date, timestamp `ts`, level family/type, fade direction `f` (+1 long fade, −1 short), simulated `pnl`. Excluded: sparse window 2025-09-28..2025-11-19, NQ roll weeks (event day or prior day).
- **Globex arm (descriptive, thin):** real `active_setups` primary rows, `is_rth=false`, ACTIVE+SHADOW, since 2026-07-09, same filters as the roster scoreboard (about 1,300 rows on about 75 nights). Marked underpowered up front: no cell may be called SHOWN on Globex alone; it is reported next to RTH so a sign reversal (the documented Globex pattern) is visible.

## Features (all from one-minute bars strictly before the event timestamp; `t` = event bar, `c[t−1]` the last closed bar)
`ATR20` = mean `rth_range` of the 20 prior sessions. For horizon `k` in {60, 240} bars: `T_k = f × (c[t−1] − c[t−1−k]) / ATR20` (positive = the k-bar move was in the fade's favour direction, i.e. fading AGAINST the higher-timeframe trend is negative `T_k`... sign convention fixed: `T_k > 0` means price rose over k bars for a long fade / fell for a short fade, which is trading WITH the larger trend; `T_k < 0` means the fade goes AGAINST the larger trend). Prior-session context: `T_S = f × (PD close − PD open) / ATR20` using the prior RTH session. The 15-bar move is NOT tested alone (the replay's direction rule already uses the 5-bar approach, so it is partly definitional); it enters only as a control.
States per feature: WITH if `T ≥ m`, AGAINST if `T ≤ −m`, else MIXED, where `m` = the median `|T|` over events of the previous 60 trading days (strictly prior; needs ≥ 100 prior events), so the cutoff is data-derived and scale-free. Composite: ALL_WITH (T_60, T_240, T_S all WITH) and ALL_AGAINST.

## Outcomes
(1) Simulated trade `pnl` of the replay (dollars, per-trade mean = sum/N, never day-weighted). (2) Forward signed return at 30/60/120 minutes, `f × (c[t+k−1] − entry)/ATR20`. The unconditional comparator is the mean over ALL events of the block (never zero).

## Cells (counted up front: 40)
Features {T_60, T_240, T_S} × states {WITH, AGAINST} × outcomes {pnl, ret30, ret60, ret120} = 24; composite {ALL_WITH, ALL_AGAINST} × 4 = 8; 8 more for the Globex arm (T_60, T_240 × {WITH, AGAINST} × {pnl, ret60}), descriptive only. Total 40.

## Test and rule (frozen)
1. Chronological split by DATE: explore = earliest 60% of event dates, hold-out = rest. All screening on explore.
2. Statistic: excess = (mean outcome | state) − (mean outcome over all events of the block), per-trade means. Day-blocked bootstrap 95% CI (resample dates, pool their events). Placebo: circular shift of the chronologically ordered event-state sequence against fixed outcomes (2,000 seeded offsets), two-sided p for screening, one-sided in hold-out.
3. Multiplicity: BH at q = 0.10 over the explore p-values of the evaluable RTH cells (those with ≥ 300 state events on ≥ 60 dates in explore).
4. **Confound control (required, before SHOWN):** stratified excess — recompute the excess within strata of (level family × time-of-day bucket [first hour, mid-day, last 90 min] × LONG/SHORT), average the within-stratum differences weighted by state events. A cell is **SHOWN** only if it is a BH survivor on explore, the hold-out excess has the same sign with one-sided p < 0.05, the stratified excess keeps the sign and at least half the magnitude, and a leave-top-1%-of-days-out check keeps the sign. Otherwise NOT SHOWN; a survivor that fails hold-out is "explore only".
5. Opposite-signed subgroups are reported for every SHOWN cell: by LONG vs SHORT, by level family, by era (pre/post 2025-06), by RTH vs the Globex arm. The pooled verdict is a question, not an answer.
6. **Survivors only:** a real fill-realistic replay (market fills, gambler's-ruin placebo for the asymmetric stop/target) of "skip or SHADOW the AGAINST/WITH fades", measured as the change in total simulated P&L and in the number of trades removed, with a day-blocked CI on the per-trade difference (kept trades vs removed trades are non-overlapping groups). A gate that removes trades must beat a random removal of the same number of trades (permutation over the same days).
7. **If implemented:** reuse the existing shadow-tag pattern (`direction_gate_shadow` / `momentum_against_fade_shadow` precedent), observation-only first; no new `acd.js` inline logic (house rule: new logic goes to `server/services/`); full 3-phase review for any live-wiring.

## Honest expectations and limits
Replay P&L is simulated and the roster is -3.5 per trade overall, so the hypothesis is a SEPARATION, not a profit claim. Cells are correlated (same events, nested horizons). The Globex arm cannot decide anything. A null is the likely result given the earlier RTH momentum-against-fade work, and the report must state what could not be shown (smallest resolvable per-trade difference).
