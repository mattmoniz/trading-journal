# Design: live SHADOW detector for the Argon liquidity-vacuum pullback (candidate Q4-4)

2026-11-08. User: "go, and I also want to wire it to see it fire in live". Shadow only: NO orders, NO writes to active_setups, NO server change, NO restart (a restart disarms the Sierra switch). Prereg for the funnel: `docs/ARGON_VACUUM_BLIND_FUNNEL_PREREG_20261108.md` (section 8 result: 0.83 triggers/session, underpowered on Explore). This process adds forward days; it is DESCRIPTIVE ("see how it fires") plus a growing forward sample. Constants are the spec's, frozen as in the prereg; none changes.

## Process
`scripts/argon_vacuum_live/shadow.py`, a standalone Python daemon (like `scripts/amt_tell_live/sidecar.py`, reusing `bootstrap.primary_paths`, `persist.contract_for`, `tailer.ScidTailer`, `session.LiveSession('split')`, the same 500-contract split bar rule). Health on 127.0.0.1:8905. Single-instance lock file. Started by hand (`scripts/argon_vacuum_live/run.sh`); wiring into start.sh is a later, separate step.

## Detection = stateless replay (parity by construction)
At every completed bar (once caught up with the tick file) rebuild the RTH slice of the session so far from the COMPLETE bars only, run the SAME functions as the batch count (`features()`, `run_fsm()`, `run_ffc()` imported from `scripts/argon_vacuum_blind_funnel.py`), and diff the trigger list with what is stored. Priors (20 prior qualifying sessions' RTH bars) come from `scratch/argon_vacuum_live/priors/DATE.bars.tsv`, filled from the tell sidecar's saved bars, the 2026-10-12..10-19 extract (dates >= 2026-10-12 only, never the sealed era) or rebuilt from ticks. All features are backward-only, so a trigger found at bar k is identical to the one the batch run would find.

## Persistence (new table `argon_vacuum_shadow`, one row per trigger, both arms)
arm ('CAND' | 'FFC'), trade_date, bar_idx, fired_at (naive ET, the real tick time of the closing trade of bar k), dir, entry_ref (close of bar k), init_risk_pts (CAND), max_pb_bars, priors snapshot (atr, act_thr, clv_hi, clv_lo, base, floor as json), decision_hash, code_version, late_min (wall clock minus fired_at, hr-013), then OUTCOME columns filled after the fact from the stored bars: fwd_10 / fwd_30 / fwd_60 = dir * (close[k+h] - close[k]) in points, clamped to the hard-flat bar, plus mfe_30 / mae_30. Decision columns are frozen at insert; a later replay that disagrees raises a DRIFT alarm (log + health), never overwrites. Outcomes only ever fill once.

## Not in scope
Orders, sizing, the Globex track (needs VB=100), the MNQ-coupled gates, ML. A forward edge claim: the forward log is exploratory until the pre-registered forward looks (a later prereg: at N active days, not before).

## Risks to review (asked of Argon High)
Restart mid-session; contract roll; early close days; the 09:30-straddling bar in live; a bar completing and the diff firing twice; the FFC arm writing ~30 rows a session; look-ahead through priors; clock skew; file rewrite by Sierra.
