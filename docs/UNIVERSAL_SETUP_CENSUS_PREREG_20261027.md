# Pre-registration: universal census and True-MTM audit of every setup — 2026-10-27

Written BEFORE any performance number was computed (schema discovery and row counts only). Origin: the user's request for an uncensored census of every setup in the database, with True mark-to-market accounting, the same 60/40 split, no N floor, and Tables 1-3.

## Schema discovery (outcome-free, done before this document)
Tables carrying a `setup_type`/`setup_id` column (main ones): **`active_setups`** (28,311 rows, 267 setup types; origins ACTIVE 1,666, SHADOW 9,285, BACKFILL 15,877, UNKNOWN 1,483; `is_rth` true/false), **`gated_candidates`** (112,473 rows, 228 types; 27,000 or so carry `would_have_entry/stop/target`, the rest are bookkeeping rows such as GLOBEX_ALREADY_FIRED_TODAY without a stop or target), `setup_outcome_backtest` (3,545 rows, every `setup_id` joins to an `active_setups.id`: a derived duplicate), `acd_setup_events` (12,535 timeline events: time and price only), `order_placements` (883 broker orders keyed by `active_setups.id`), `trade_timeline_events`, `dynamic_edges_mining`, `setup_move_stats`, `setup_daytype_winrates` (statistics tables), `trades` (the user's own trades: `setup_type` is NULL on every row; excluded by the standing rule against using it as signal evidence), plus about 50 `*_backup_*` snapshot tables of `active_setups`/`trade_timeline_events`/`order_placements` (listed as one line, never counted twice). Only `active_setups` and the full-price part of `gated_candidates` hold a complete trade record (entry, stop, target, time) and can be re-simulated; every other table is listed in Table 1 with the reason it is not.
Environments: `active_setups.origin_status` ACTIVE = Live (shown live), SHADOW = Shadow, BACKFILL = Backfill (a simulation, with the construction caveats of `backfill_stop_target_in_sample_percentiles_20261027`), UNKNOWN = pre-2026-07-09 origin unrecoverable; `gated_candidates` = Gated candidate (a setup evaluated and blocked by a risk gate, never entered). No Paper environment exists as a separate table; SHADOW is the paper/background population. Session class is taken from the ENTRY BAR clock, not `is_rth`: RTH 09:30-15:59, Post-close 16:00-16:59, Globex 18:00-09:29.

## Population and exclusions (every excluded row is counted by reason in Table 1b; nothing is dropped silently)
Raw N = all rows of the source for that (setup, environment). Not simulated, with reason: stored `resolution` NOT_FILLED / NO_PRICE_DATA (never entered); missing stop or target; no direction (`resolveDirection` null); no bar at the fired minute; trade date inside an NQ roll week or the 2025-09-28..2025-11-19 sparse-bar window (bars unreliable); entry price outside the fired minute's bar range +/- 0.5 (not an immediate fill; resting-entry rows cannot be simulated without inventing a fill model); session not complete in the data (open positions of the last day). Rows carrying a `*_basis` flag are INCLUDED (counted per environment in Table 1b). Cluster siblings are included (they are other setups' rows). All bars are NQ `price_bars_primary`; point value 2 dollars (MNQ).

## Engine (identical to `study_true_mtm_decomposition_20261027.mjs`, which reproduced the pooled 1,723-trade book exactly)
Immediate entry at the stored entry price on the fired-minute bar; stop checked on the entry bar (conservative), target not credited there; later bars: gap through the stop fills at the open, stop touch fills at the stop, then the same for the target, stop before target. Stop, target and expiry are the NATIVE stored values (`stop_level`, `t1_level`, `expires_at`; gated candidates: `would_have_stop/target`, no stored expiry so the session cap is the expiry). Expiry bar = stored expiry capped at the end of the entry bar's session (RTH 15:59, Post-close 16:59, Globex 09:29 of the trade date). **No trade is scored at 0: unresolved at expiry = marked to the close of the expiry bar.** Gross = `d x (exit - entry) x 2`; Net_$1 = gross - 1; Net_$4 = gross - 4. Dynamic exits that the live system used for some setups (wider targets, runner trails, breakeven stops, rotation flips, designed time exits) are NOT modeled; this is a uniform native-stop/target re-simulation, not a replay of what the live system did, and the stored P&L mean is printed beside it.
Mode 1 deduplication: independently within each (setup, environment), no overlapping open same-direction trade on the same trade date, order `(trade date, entry bar, id)`, overlap judged on the engine's simulated exit bar. Train = trade date <= 2026-01-02 (the 60 percent cut of the 336 RTH dates), Hold-Out = later; for Live/Shadow/Gated data the Hold-Out also contains dates after 2026-07-21 (the 336-date set ended there) and the 2026-10-11/12 structural-change boundary falls inside it.

## Added audit layer (the user's tables are printed unchanged; these say how to read Table 3)
With no N floor and hundreds of groups, Table 3 will contain many groups by chance. (a) **Survivor-count placebo:** within-date permutation of the setup labels among the Mode 1 trades of each environment (Train and Hold-Out kept intact, group sizes kept), 500 permutations, the same survivor rule; reported for all groups and for groups with Train N >= 20 and Hold-Out N >= 20. (b) **Persistence test:** pooled Hold-Out mean of trades in groups whose Train mean was positive minus that of groups whose Train mean was <= 0 (trade-weighted, date-blocked 95 percent interval), for all groups and for Train N >= 20: if Train sign predicts Hold-Out, the difference is positive.
**What the output can and cannot say:** a census of in-sample re-simulated trades on spent history. A group in Table 3 is a lead only; with Hold-Out N < 5 allowed it is not even a Hold-Out result. Nothing here promotes or demotes a live setup.
