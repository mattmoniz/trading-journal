# Design review — FLOOR_ES_LATE_CONFIRM_PREREG_20261026.md

Numbered findings, most serious first.

1. **L2 is algebraically identical to L1, not a second primary.** In L2 both the treatment and the control differences subtract the SAME event's NQ-fire ret60, so they cancel exactly: DiD = [ES-confirm − NQ-fire] − [blind-later − NQ-fire] = ES-confirm − blind-later = L1. The claimed "control for the structural cost/benefit of a later entry" is nothing but L1's delay-matched control; the NQ-fire baseline contributes zero. Counting "two primaries" (L1+L2) for Bonferroni is therefore mis-specified. Fix: make L1 the single primary; report the raw paired ES-confirm − NQ-fire as descriptive if "waiting for ES beats firing on NQ" is still wanted.

2. **The delay-matched control does not isolate ES's information.** The blind control is unconditional on NQ's turn, so L1 = ES-confirm entry − blind entry conflates the NQ-turn edge with ES's added info; a SHOWN L1 could be entirely NQ. Worse, the control's delay pool is the LATE events' own confirmation delays — a post-selection, right-censored distribution that only exists because ES confirmed (survivorship), so it is not "blind." Fix: add an NQ-turn-conditioned control (entry at a matched delay where NQ has fired but ES has NOT confirmed — e.g. NEVER events entered at LATE's delay distribution) so ES is the only difference; draw control delays from the all-fires delay distribution and print treatment vs control delay histograms.

3. **Survivorship/selection.** LATE is by construction "price kept going the right way long enough for ES to rise 0.25×A15_ES," and with NQ-ES corr ≈ 0.916 the descriptive LATE vs NEVER vs SAME-OR-EARLIER ret60 is near-tautological. It is labeled descriptive, but the class shares and the "how long the queue waits" distribution are right-censored at W (NEVER is excluded), understating the wait. Fix: report wait time as a censored distribution including NEVER; put the selection-confounded caveat in the table/figure caption, not only the methods.

4. **Lookahead in the control pool / halves.** The delay pool uses full-sample LATE delays, so future events' delays leak into the matching distribution, while "chronological halves both positive" splits only the events. Fix: sample control delays only from the same chronological half as the focal event (explore delays for explore events).

5. **Power.** LATE is a subset of DISAGREE (≈18–28% of fires), further split into halves, with a 97.5%-coverage CI and a fragile "both halves positive" gate. Dropping the redundant L2 removes half the multiplicity, but the single remaining primary is still likely underpowered. Fix: pre-specify expected LATE counts from the parent JSON; print the smallest detectable effect per cell; state NOT SHOWN as "unresolved below the resolution bar," never "ES adds nothing."

6. **Wording/robustness.** "98.75 percent intervals" conflates the upper percentile with coverage (1.25th–98.75th = 97.5% coverage, the correct Bonferroni α=0.025 two-sided). The VAH mirror and RTH/Globex split are descriptive, so a long-floor SHOWN that the mirror contradicts should be flagged. Fix: correct the CI wording; require the mirror to not contradict before any long-floor result is treated as forward-worthy.
