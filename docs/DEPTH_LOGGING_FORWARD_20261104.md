# Forward order-book depth logging (adopted by the user 2026-11-04: 'Yes to both'; Opus review, `docs/MARKET_MODEL_DESIGN_BRIEF_20261104.md` section 8)

## What runs
`scripts/depth_persec_nightly.sh`, a step of `scripts/run_daily_calibration.sh` (8:20 PM ET Mon-Fri): for today and the two previous weekdays it runs `scripts/depth_persec_20261021.mjs` on the trade date's largest Sierra `.depth` file (either Sierra data folder) and keeps the RTH per-second summary in `scratch/depth_persec_20261021/DATE.CONTRACT.tsv` (columns: second since midnight ET, best bid, best ask, size at the best bid and ask, resting size within 10 ticks each side, within 40 ticks each side). Forward-only from 2026-11-04: the 2026-06-15 to 2026-11-03 depth sessions sit inside the sealed hold-out era and are NOT mined. Outcome-blind (never reads a trade or P&L), idempotent (a file is kept only if written after 16:05 ET of its date, so a partial file is rebuilt), a failed day is retried the next night and never fails the daily job. The raw 1 GB a day files are untouched.
## How it will be used (and not used)
Nothing reads it today and nothing trades on it. It is a dataset that grows with honest, outcome-free rows. After about 120 fresh sessions (about six months, roughly May 2027) ONE pre-registered test: does a depth feature (resting size near price now versus its own 20-day norm for the same time of day, how fast the approached side thinned or refilled over the last 1-5 minutes) add to a baseline of HAR-X + clock + the intraday groups for the next-hour range, with the same placebo gate, both halves and day-block bootstrap as the HAR test; about 250 sessions before it could enter any live model, and only if the 120-session test passed. If depth adds nothing at 250 sessions, stop recording and record the null with exactly what was tested. Depth is a HOW-MUCH input, not a direction input (the earlier sweep and absorption tests were direction calls and were null).
## Limits
Per-second snapshots, not tick-by-tick order events (the true replenishment rate needs the raw files); the depth feed records limited levels; the Sierra depth file layout is as verified in `scripts/depth_absorption/depth_reader.py`; disk: about 1 MB a day for the summaries.
