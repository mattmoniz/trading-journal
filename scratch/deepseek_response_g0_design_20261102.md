## 1. Entry freshness gate (section 1)

The direction is right, but two aspects are under-specified and one is over-broad.

**Placement / the "N min old" reason is not free.** The design wants `recordEntrySkip(row, "price feed stale: latest NQ bar N min old")`, but the helper it cites (`getLatestBars()`, priceRetrieval.js:50-68) already collapses "stale" into an empty `[]` and discards the age. To print "N min old" you need a *new* raw-age read (or a change to the helper), not the helper as-is — otherwise stale, no-rows, and query-error all look identical and you cannot distinguish "20 min old" from "table empty". Specify that the age is computed with `etNaiveTimestampToMs()` (the banner code documents a real 4-5h ET/UTC bug at setups.js:90-97); a naive `Date.parse` would false-stale every fresh bar.

**Over-broad: gating LIMIT entries.** `wantsMarketEntry()` (orderSweep.js:149-153) already separates MARKET (moving reference: VWAP/magnet/rotation) from fixed-level LIMIT entries whose `entry_zone_low` is a frozen level in `level_prices`, not live price. A resting LIMIT at a frozen level has *no* freshness dependency; blocking it for a stale feed is a false block that silently costs entries with zero safety gain. The sharpest correctness argument applies only to `marketEntry === true` (and the escalate-to-market path, which already fails closed at orderSweep.js:344-354 via `getCurrentPrice()==null`). Make the gate MARKET-only, or state explicitly why LIMIT is included.

**Visibility is not what the design implies.** `recordEntrySkip` writes `gate_name='SIERRA_ENTRY_SKIP'` with the reason prefixed `setup_id=…` (orderSweep.js:194-212). There is no `FEED_STALE` gate_name, so the nightly "count of FEED_STALE skips" is a regex over `gate_reason`. Worse, the banner is a *different* threshold (10 min) with an `isGlobexWeekClosed` guard (setups.js:106), while the helper is 15 min with no closure guard — so the banner can read "not stale" while the gate blocks (or vice versa). "Reuse priceBarsStale" is loose; unify the threshold/guard across banner, helper and gate, or the operator sees a contradiction. Also note: `recordEntrySkip` dedups per setup+reason over 5 minutes (orderSweep.js:207-211), so a persistent outage produces at most one row/setup/5-min — fine, but the attestation count must not interpret dedup as "resolved".

**False-stale in thin Globex** is real and is precisely the reason to (a) use a closure-aware guard and (b) not tighten below 15 min without data. The "no-static-threshold" rule (hr-003) explicitly exempts infra/operational thresholds, so 15 is defensible; the real defect is having *three* divergent numbers for the same quantity.

## 2. Boot self-test (section 2)

Two concrete problems.

**The design's DLL assertion is wrong against current code.** `dllGateDecision` with unknown P&L *and a computable worst case* now returns `blocked:false` (dllGate.js:29-35, the 2026-10-18 change) — unknown-with-a-stop is counted at worst-case, not blocked. It only blocks when `unknownWorstCaseLoss` is null (no stop/no price) or worst-case reaches the limit. "Returns blocked for unknown P&L" as a *general* claim would make the self-test fail on any ordinary unknown-P&L trade. The wired `evaluateDailyLossLimit` *does* fail closed on an unset limit (dllGate.js:84-86), so that half is correct — but the two behaviors are separate and must be asserted separately.

**The auto-rearm interaction is un-plumbed and racy.** `maybeAutoRearmAfterReconcile()` (connectionManager.js:138-150) consults only `DTC_AUTO_REARM_SAFE`, `armed`, `lastReconciliationReport.clean`, and the invariant check. It fires on the *first* LOGON reconciliation, which `connectOnce()` triggers asynchronously right after `forceHaltOnBoot()`. A self-test that "runs after boot, before any auto-rearm" has no defined ordering against that LOGON, and "suppress the auto-rearm" requires a *new* gate in that function that nothing currently reads. This is exactly the repo's own rule: "a re-arm gate must require EVERY independent check that can halt" (where_to_look wl-010/138). Specify: the self-test must run to completion (with a timeout, failure non-fatal to boot) *before* `connectOnce()`/first reconcile, and its result must be an input to `maybeAutoRearmAfterReconcile`.

**Safety of the mock sweep.** `sweepRealOrders` early-returns when `!dtcClient.isLive()` (orderSweep.js:175), so a mock must fake `isLive()===true` to exercise anything — and then `sweepExits` (orderSweep.js:419-469) runs and does *not* consult the kill switch, so against the live DB it can write EXIT rows / submit against the mock. Test the three gates (`isOrderEligible`, `checkEntryGates`, `evaluateDailyLossLimit`) as pure units plus a rolled-back insert; do **not** run the full `sweepRealOrders` against a live DB.

## 3. Failure rehearsal (section 3)

Order by (a) no-broker, (b) automated, (c) increasing blast radius. Automate first: (1) duplicate server process and tick-file-missing at session start (pure infra, `server-lifecycle.sh` already detects duplicates); (2) stale feed with a resting entry (inject bar ages into the new gate — this doubles as the gate's acceptance test); (3) DTC disconnect mid-order against an offline mock. Then manual, on the sim (auto-rearm) account: (4) restart mid-position, (5) exit-rejected-then-retried against a different position (this exercises the 2026-10-18 retired-exit path), (6) sleep/wake. 4-6 need a written pass/fail checklist and a read of `gated_candidates`/`order_placements`/`live_attestations` after each, because broker-side truth can't be asserted in-process.

## 4. Red team

- **Gate (s1):** a false-stale (naive timestamp, wrong column, empty table) blocks entries silently — the reason string is the only trace and it's deduped. Prove with a unit test that injects a *fresh* bar and asserts entries proceed, and a test that feeds an ET-naive string and asserts the age is computed via `etNaiveTimestampToMs`. The gate must also be placed *outside* the per-row `try/catch` but *inside* `sweepEntries`, so a throw skips entries while `sweepExits`/escalation still run (they already do).
- **Self-test (s2):** it could itself arm/disarm or write rows. Prove by byte-diffing the state file and DB before/after (repo rule hr-010), and by forcing a self-test failure on a `DTC_AUTO_REARM_SAFE` profile and asserting the switch stays disarmed after LOGON.
- **Rehearsal (s3):** a mis-pointed env could rehearse against a real account. Prove by making the script hard-refuse unless `DTC_AUTO_REARM_SAFE==='true'` *and* the profile header confirms non-real, and never call `arm()`/`halt()` on the kill switch.

The 3 most important changes: (1) make the freshness gate MARKET-only and unify its threshold/guard with the 10-min banner and 15-min helper; (2) correct the self-test's DLL assertion (unknown-with-worst-case does not block) and explicitly sequence it before the first LOGON reconcile, with its result as a gate in `maybeAutoRearmAfterReconcile`; (3) reject running the full `sweepRealOrders` against a live DB in the self-test — test the three gates as pure units plus a rolled-back insert.
