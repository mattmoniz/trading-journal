NQ Meta-Labeling Filter: Implementation Specification
Purpose: Build a machine-learned entry filter that sits on top of your existing signal generator. Your system keeps firing signals exactly as it does today. The filter learns, from historical outcomes, which signal instances are likely to be profitable, and vetoes the rest.

What this is (meta-labeling): You already have a primary model — your existing signal logic. Meta-labeling does not try to replace it or predict direction. It trains a secondary model to answer a narrower question: "Given that the primary signal fired, in this market context, what is the probability this specific instance reaches target before stop?" This is a much more tractable problem than predicting direction from scratch, and it is the technique with the best track record in systematic trading.

What this is NOT:

It is not a direction predictor.

It does not modify your signal generation logic.

It does not change your exits.

It is a pass/veto gate on entries.

Prerequisites:

nq_bars table populated with 2 years of NQ 1-minute Sierra Chart data (see Section 1).

Your existing signal generator can be run in historical replay mode over that data.

Express backend (port 3002) and PostgreSQL trading_journal are running.

Stack:

Express (port 3002) — existing

PostgreSQL trading_journal — existing

Python 3.11 microservice (port 5001) — new

LightGBM, pandas, scikit-learn, psycopg2

Non-negotiable principles:

Every raw signal is logged to raw_signals before any filter runs. No exceptions.

Outcomes (labels) are computed for every logged signal via forward replay of price. No manual tagging.

No model is trained on data it has not genuinely seen in the future. Purged walk-forward CV only.

The final test set is touched once, at the very end. Not once per iteration.

The model ships in shadow mode for at least 14 days before gating live trades.

All timestamps UTC.

2.3 Historical backfill
To train the filter, you need historical signals. Run your existing signal generator in replay mode over the 2-year nq_bars history. For every historical signal it fires, insert a raw_signals row with the historical timestamp, price, strategy, and direction.

3.2 Feature definitions (exact)
All computed at the signal bar timestamp t. All rolling windows strictly ≤ t. This is the leakage boundary.

Time context

minutes_since_rth_open = minutes from 09:30 ET to t.

minutes_until_rth_close = minutes from t to 16:00 ET.

day_of_week = t.dayofweek (0=Mon, 4=Fri).

is_first_30min = minutes_since_rth_open <= 30.

is_last_30min = minutes_until_rth_close <= 30.

Session structure — RTH = 09:30–16:00 ET. "Session so far" = bars from 09:30 ET today through t.

dist_to_session_high_ticks = (session_high − close) / TICK_SIZE (signed).

dist_to_session_low_ticks = (close − session_low) / TICK_SIZE (signed).

dist_to_rth_open_ticks = (close − rth_open) / TICK_SIZE (signed).

dist_to_vwap_ticks = (close − vwap_session) / TICK_SIZE (signed).

session_range_ticks = (session_high − session_low) / TICK_SIZE.

Prior-day (PD) — prior RTH session's high, low, close.

Each distance = (close − pd_level) / TICK_SIZE, signed.

pd_range_ticks = (pd_high − pd_low) / TICK_SIZE.

Volatility — raw ranges, no indicators.

range_mean_20 = mean of (high − low) over last 20 bars.

range_mean_60 = same over 60.

range_percentile_500 = percentile rank of current bar's range within last 500 bars, in [0,1].

abs_move_last_5_ticks = |close_t − close_{t−5}| / TICK_SIZE.

abs_move_last_20_ticks = |close_t − close_{t−20}| / TICK_SIZE.

Volume / order flow

volume_last_5 = sum of volume over last 5 bars.

volume_last_20 = same, 20 bars.

relative_volume_20 = volume_last_5 / (volume_last_20 / 4).

delta_last_5 = sum of (ask_volume − bid_volume) over last 5 bars. Null bid/ask treated as 0.

delta_last_20 = same, 20 bars.

cvd_slope_5 = OLS slope of session cumulative delta over last 5 bars. Session cumulative delta = running sum of (ask_volume − bid_volume) from RTH open.

cvd_slope_15, cvd_slope_30 = same windows.

Auction market context — computed over RTH session so far.

vwap_session = sum(typical_price × volume) / sum(volume) where typical_price = (high+low+close)/3, RTH bars only.

poc_price = price level (rounded to tick) with highest total volume in session, bucketing each bar's volume across its high–low range.

value_area_high / value_area_low = contiguous price range containing 70% of session volume, centered on POC.

dist_to_vah_ticks, dist_to_val_ticks, dist_to_poc_ticks = (close − level) / TICK_SIZE, signed.

poc_migration_up = poc_price(t) > poc_price(t − 60 bars).

poc_migration_down = poc_price(t) < poc_price(t − 60 bars).

Structure at signal

hh_last_20 = high_t == max(high) over last 20 bars.

hl_last_20 = low_t > low_{t−1} AND low_{t−1} > low_{t−2} AND low_{t−2} > low_{t−3}.

lh_last_20, ll_last_20 = mirrors.

bars_since_last_swing_high = bars since most recent swing high. Swing high = bar whose high strictly exceeds highs of the 2 bars on each side (5-bar fractal).

bars_since_last_swing_low = mirror.

Signal self-context

bars_since_last_signal = bars since previous raw_signals row with same strategy_name.

direction, strategy_name = copied from raw_signals.

4.2 Barrier values (derived from Section 0)
Let R_range = range_mean_20(t) be the reference volatility at signal time.

Stop distance:

FIXED_TICKS → EXIT_STOP_VALUE ticks

ATR_MULT → EXIT_STOP_VALUE × R_range ticks

Target distance:

FIXED_TICKS → EXIT_TARGET_VALUE ticks

ATR_MULT → EXIT_TARGET_VALUE × R_range ticks

EXTENDED → EXIT_TARGET_VALUE × (current fixed target) — i.e., a multiple of what you'd normally use

Time barrier: EXIT_MAX_HOLD_BARS bars from signal.

Both barriers are absolute price distances from entry_price.

4.3 Labeling algorithm (exact)
python
def label_signal(signal_id, conn, bars_cache, tick_size,
                 stop_ticks, target_ticks, max_hold_bars,
                 slippage_ticks, commission_rt_usd, tick_value_usd):
    sig = fetch_signal(signal_id, conn)
    entry = float(sig["entry_price"])
    direction = sig["direction"]
    t0 = sig["ts"]

    forward = bars_cache.loc[bars_cache.index > t0].head(max_hold_bars)
    if len(forward) < 2:
        return None

    if direction == "BUY":
        stop_price = entry - stop_ticks * tick_size
        target_price = entry + target_ticks * tick_size
    else:
        stop_price = entry + stop_ticks * tick_size
        target_price = entry - target_ticks * tick_size

    mfe = 0
    mae = 0
    exit_price, exit_reason, bars_held = None, None, None

    for i, (ts, bar) in enumerate(forward.iterrows(), start=1):
        if direction == "BUY":
            mfe = max(mfe, int((bar["high"] - entry) / tick_size))
            mae = max(mae, int((entry - bar["low"]) / tick_size))
            hit_stop = bar["low"] <= stop_price
            hit_target = bar["high"] >= target_price
        else:
            mfe = max(mfe, int((entry - bar["low"]) / tick_size))
            mae = max(mae, int((bar["high"] - entry) / tick_size))
            hit_stop = bar["high"] >= stop_price
            hit_target = bar["low"] <= target_price

        # Tie-break: stop wins if both hit same bar
        if hit_stop:
            exit_price, exit_reason, bars_held = stop_price, "STOP", i
            break
        if hit_target:
            exit_price, exit_reason, bars_held = target_price, "TARGET", i
            break

    if exit_reason is None:
        exit_price = float(forward.iloc[-1]["close"])
        exit_reason = "TIME"
        bars_held = len(forward)

    gross_ticks = (
        (exit_price - entry) / tick_size if direction == "BUY"
        else (entry - exit_price) / tick_size
    )
    commission_ticks = (commission_rt_usd / tick_value_usd)
    net_ticks = gross_ticks - (2 * slippage_ticks) - commission_ticks

    label = 1 if exit_reason == "TARGET" else 0

    return {
        "signal_id": signal_id,
        "exit_reason": exit_reason,
        "bars_held": bars_held,
        "exit_price": exit_price,
        "mfe_ticks": mfe,
        "mae_ticks": mae,
        "pnl_ticks": int(net_ticks),
        "label": label,
    }
4.4 Tie-breaking rule (mandatory)
If a single bar's high and low both breach stop and target, assume the stop was hit first. Conservative. Prevents systematically inflating the label distribution.

4.5 Training view
sql
CREATE VIEW v_ml_dataset AS
SELECT f.*, l.label, l.pnl_ticks, l.exit_reason, l.bars_held,
       l.mfe_ticks, l.mae_ticks, r.ts
FROM signal_features f
JOIN signal_labels l USING (signal_id)
JOIN raw_signals r USING (signal_id)
WHERE r.status IN ('EXECUTED', 'PENDING', 'VETOED_RISK', 'VETOED_MANUAL', 'VETOED_LOCK');
Excluded: VETOED_ML rows. They were vetoed by a previous version of the model and their inclusion would bias training toward the model's own past decisions. They are still logged for monitoring.

5.3 Purged walk-forward CV (mandatory)
python
def purged_walk_forward(df, n_splits=5, purge_bars=None):
    if purge_bars is None:
        purge_bars = EXIT_MAX_HOLD_BARS
    df = df.sort_values("ts").reset_index(drop=True)
    n = len(df)
    fold_size = n // (n_splits + 1)
    for k in range(1, n_splits + 1):
        train_end = k * fold_size
        test_start = train_end + purge_bars
        test_end = min(test_start + fold_size, n)
        if test_start >= n:
            break
        yield (
            df.iloc[:train_end].index,
            df.iloc[test_start:test_end].index,
        )
Why purge_bars = EXIT_MAX_HOLD_BARS: if two signals are within EXIT_MAX_HOLD_BARS of each other, their outcome windows overlap. Training on one and testing on the other leaks information.

5.4 Training procedure
Split v_ml_dataset by time: first 80% for CV training, last 20% held as final test. Do not touch the final test until Section 6.

Run purged walk-forward CV on the 80% with 5 folds.

For each fold, train a fresh model, evaluate on held-out fold.

Report per-fold: precision, recall, AUC, base rate, lift @ top decile.

Retrain on full 80% with same hyperparameters. Save.

5.5 Required metrics per fold
Metric	Formula	Target
Base rate	mean(y_test)	—
Precision	TP / (TP + FP)	≥ base rate + 0.10
Recall	TP / (TP + FN)	≥ 0.30
AUC	roc_auc_score(y_test, proba)	0.55–0.70
Lift @ top decile	precision of top 10% by predicted proba ÷ base rate	≥ 1.5
Interpretation:

AUC > 0.80 → leakage. Audit features for future data.

AUC ≈ 0.50 → no signal. Model is noise. Do not proceed.

Precision < base rate → model is anti-correlated. Bug.

Recall < 0.15 → threshold too strict.

5.6 Confidence threshold selection
Default = 0.60. To tune, sweep [0.50, 0.55, 0.60, 0.65, 0.70, 0.75] on the CV folds:

text
E[value_per_signal] = P(win | p ≥ t) × avg_win_ticks
                    − (1 − P(win | p ≥ t)) × avg_loss_ticks
Choose the threshold maximizing E[value_per_signal] subject to at least 50 signals in CV test folds at that threshold.

6.2 Metrics on test set only
Metric	Baseline	Filtered	Pass
Signal count	N	M	M ≥ 30
Win rate	b	f	f > b
Avg PnL per signal (ticks)	x	y	y > x
Profit factor	pf_b	pf_f	pf_f > pf_b
Max consecutive losses	c_b	c_f	c_f ≤ c_b
6.3 Go/No-Go criteria (all must pass)
M ≥ 30

f ≥ b + 0.05

y ≥ x + 2 ticks

pf_f ≥ 1.3

c_f ≤ c_b

If any fails: the model is not deployable. Iterate on features, not hyperparameters. Feature quality dominates.

Do not re-run the test set with different thresholds and cherry-pick the best. That converts a valid out-of-sample test into an overfit in-sample test. Test once. If the answer is "no," collect more data or revise features, then use a new held-out window.

Section 8: Express Integration
8.1 Signal handler order
text
1. Insert raw_signals row
2. Call POST /snapshot   → compute features (if not already cached)
3. Call POST /predict    → get probability and decision
4. Write ml_decisions row
5. If decision == VETO: update raw_signals.status = 'VETOED_ML' and return
6. Otherwise proceed to risk checks + execution
8.2 Decisions table
sql
CREATE TABLE ml_decisions (
    id              BIGSERIAL PRIMARY KEY,
    signal_id       UUID NOT NULL REFERENCES raw_signals(signal_id),
    model_version   VARCHAR(40) NOT NULL,
    probability     NUMERIC(5,4) NOT NULL,
    threshold       NUMERIC(5,4) NOT NULL,
    decision        VARCHAR(10) NOT NULL CHECK (decision IN ('TAKE','VETO')),
    mode            VARCHAR(10) NOT NULL CHECK (mode IN ('SHADOW','LIVE')),

);

CREATE INDEX idx_ml_decisions_signal ON ml_decisions(signal_id);
CREATE INDEX idx_ml_decisions_created ON ml_decisions(created_at DESC);
8.3 Shadow mode
Add system_config key meta_labeling_mode with values OFF, SHADOW, LIVE.

In SHADOW mode:

/predict is called on every signal.

Row written to ml_decisions with mode='SHADOW'.

The actual execution decision is unaffected. System runs exactly as before.

Minimum shadow period: 14 calendar days, with at least 50 signals where the model returned VETO.

8.4 Shadow evaluation
After the shadow period:

sql
SELECT
  COUNT(*) FILTER (WHERE decision = 'TAKE') AS take_count,
  COUNT(*) FILTER (WHERE decision = 'VETO') AS veto_count,
  AVG(CASE WHEN decision = 'TAKE' THEN l.pnl_ticks END) AS avg_pnl_taken,
  AVG(CASE WHEN decision = 'VETO' THEN l.pnl_ticks END) AS avg_pnl_vetoed,
  SUM(CASE WHEN decision = 'TAKE' AND l.label = 1 THEN 1 ELSE 0 END)::float
    / NULLIF(COUNT(*) FILTER (WHERE decision = 'TAKE'), 0) AS win_rate_taken,
  SUM(CASE WHEN decision = 'VETO' AND l.label = 1 THEN 1 ELSE 0 END)::float
    / NULLIF(COUNT(*) FILTER (WHERE decision = 'VETO'), 0) AS win_rate_vetoed
FROM ml_decisions d
JOIN signal_labels l USING (signal_id)
WHERE d.mode = 'SHADOW';
8.5 Shadow promotion criteria (all must pass)
veto_count >= 50

avg_pnl_vetoed < 0 — model correctly rejects losing signals

win_rate_taken > win_rate_vetoed + 0.05

avg_pnl_taken > 0

If any fails: do not promote. Re-tune threshold and re-shadow 14 days, or abandon the model.

8.6 Live mode
When promoted:

UPDATE system_config SET value='LIVE' WHERE key='meta_labeling_mode'.

In signal handler, if decision is VETO, set raw_signals.status='VETOED_ML' and return.

Log ml_decisions with mode='LIVE'.

8.7 Interaction with direction lock and continuation model
The filters run in this order:

Meta-labeling filter (entry gate)

Direction lock (opposite-side gate)

Risk controls

Execution

If the meta-labeling filter vetoes, the signal never reaches the direction lock. If the direction lock vetoes, the signal never reaches risk or execution.

Both filters can veto. First veto wins.

The continuation model does not participate in this flow. It only activates once a trade is open and reaches target. It is a separate, later decision point.

9.4 Champion / challenger
The retrained model is a challenger. It shadows for 14 days with the same promotion criteria as Section 8.5. Only then does it become production. The incumbent moves to ARCHIVED.

9.5 Drift monitoring (add after 3 months live)
Log daily:

Rolling IC = Spearman correlation between probability and label over last 100 labeled signals. Alert if < 0.05 for 5 consecutive days.

Rolling win rate of live-taken trades over last 50. Alert if < 0.25.

Do not auto-retrain on drift triggers. Require human review. Automated retraining on drift triggers is how systems chase noise.

10.3 Data integrity (run every 15 minutes)
sql
-- Signals older than 10 min without features
SELECT COUNT(*) FROM raw_signals r
LEFT JOIN signal_features f USING (signal_id)
WHERE f.signal_id IS NULL AND r.created_at < NOW() - INTERVAL '10 minutes';

-- Signals older than 30 min without label
SELECT COUNT(*) FROM raw_signals r
LEFT JOIN signal_labels l USING (signal_id)
WHERE l.signal_id IS NULL AND r.ts < NOW() - INTERVAL '30 minutes';

-- Live decisions without a corresponding label after 2 hours
SELECT COUNT(*) FROM ml_decisions d
LEFT JOIN signal_labels l USING (signal_id)
WHERE d.mode = 'LIVE' AND l.signal_id IS NULL
  AND d.created_at < NOW() - INTERVAL '2 hours';
All must return 0. Any non-zero fires an alert.

If, after promotion to live:

Live win rate < 0.25 over any 50 consecutive taken trades, or

Live avg PnL per signal < 0 over any 50 consecutive taken trades, or

Model artifact corruption or service failure

UPDATE system_config SET value='OFF' WHERE key='meta_labeling_mode'. System reverts to unfiltered behavior immediately.

UPDATE ml_deployments SET status='ARCHIVED' WHERE status='PRODUCTION'.

Section 14: What Success Looks Like
Fewer trades taken — typically 40–70% of raw signals survive the filter.

Higher win rate on taken signals — 5–15 percentage points above raw.

Positive avg PnL per taken signal — even if raw signals average negative.

Vetoed signals are genuinely worse — their avg PnL measurably more negative than taken signals.

If any of these don't hold after 4 weeks live, roll back. A filter that doesn't demonstrably improve outcomes is worse than no filter — it adds complexity and gives false confidence.

Three things to know before you hand this to Claude:

This must be built before v2. V2's continuation model depends on raw_signals, signal_features, and signal_labels — all defined here. Without this spec implemented, v2 has nothing to build on.

Section 15 has one decision that changes everything downstream: EXIT_TARGET_TYPE. If you set it to EXTENDED, the filter selects signals with run potential (good for your stated goal of base hits + home runs). If you leave it as FIXED_TICKS, the filter selects signals that hit your current target — which reinforces your current behavior, including the "cut winners short" problem. Set it to EXTENDED before you start. This is the single most impactful choice in the document for your stated goal.

The build order is non-negotiable. Sections 1–4 are data plumbing. Section 5 is training. Section 6 is the one-shot test. Sections 7–9 are deployment. Sections 10–15 are operations.
