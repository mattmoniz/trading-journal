# Design: live override of the tell on the SIMULATED account (2026-11-03 night, DRAFT for DeepSeek design critique, nothing built)

User go (2026-11-03): the project's point is to override the tell live; "build it, review it, restart". Start with ONE mechanism, the FLIP of fires the overlay marks AGAINST (its stop just beyond the value edge it defends); the value-edge stop for other fires (book B) is built behind its own switch, OFF. Sim capital only (DTC-Live-Simulator), 1 MNQ. Related: `server/services/amtTellOrders.js` (the existing tell-to-orders bridge, Stage 2), `docs/TELL_WATCHER_AND_SHADOW_BOOKS_DESIGN_20261103.md` (books A/B/C, same exit code as the tell), `scripts/tell_context/{reader,shadow}.py`.

## 1. Flow
1. Tell fires: row in `amt_tell_trades` (V1, split). 2. Within about a second `reader.py` writes its context row (`tell_context_fires`) and the three shadow books (`tell_shadow_trades` A/B/C, simulated with the tell's own `run_position`). 3. `amtTellOrders.considerEntries()` (every 5 s) chooses the BOOK TO FOLLOW for the fire: C if label AGAINST and override.flip, else B if override.edgeStop and B differs from the tell, else the tell (A, today's behaviour). 4. It writes the ordinary `active_setups` row for the chosen book's direction and stop (no new order-submission code: sweepEntries places the MARKET entry, reconciliation places the broker STOP at `stop_level`). 5. Exits mirror the chosen book: when its shadow row is CLOSED, the service resolves the setup with that row's exit reason (STOP / STOP_GAP / FADE / TIMEOUT / EOD) and sweepExits flattens; the broker stop can end it first (broker truth wins, as now).
## 2. Changes in `amtTellOrders.js`
- `AMT_TELL_ORDERS.override = { enabled: true, flip: true, edgeStop: false, waitMs: 20000 }`; `enabled:false` restores the pure tell (one switch).
- Pure `chooseBook(t, ctxRow, shadowRows, cfg, ageMs)` -> {book: 'A'|'B'|'C'|'WAIT', reason}. WAIT while the context row or the chosen book's shadow row is missing and the fire is younger than waitMs and still fresh on the detector's bar clock; after waitMs or when no longer fresh it returns A (the tell as it fires). UNKNOWN / NEUTRAL / AGREES -> A (or B when edgeStop is on).
- `decideEntry` gets the EFFECTIVE trade {direction, stop_price, entry_price} of the chosen book (the freshness and the 'price already through the stop' checks use the effective direction and stop). `buildInsert` and the re-link lookup use the effective direction (`AMT_TELL_LONG` / `AMT_TELL_SHORT`).
- `amt_tell_trades.order_state` records the choice: `LINKED` (tell), `LINKED_B`, `LINKED_C` (varchar(16) fits).
- `syncExits` follows the linked book: LINKED -> the tell's closed row (unchanged); LINKED_B / LINKED_C -> the matching `tell_shadow_trades` row when CLOSED (pseudo trade object with exit_reason, net_dollars, exit_points, entry_price, direction from the shadow row; resolved_at = the row's `updated_at`; `decideExit` unchanged).
- `reconcile`'s AMT_STUCK_ACTIVE check currently fires when the tell's row is CLOSED and the setup still ACTIVE for 3 minutes; for LINKED_B/C setups it must test the SHADOW row instead, and a new alarm `AMT_OVERRIDE_STALE` (pausing) fires when a LINKED_B/C setup is ACTIVE while its shadow row is still OPEN and has not been updated for 5 minutes (the reader is down; the broker stop and the 15:57 backstop still protect the position).
## 3. Safety
Same account, kill switch, daily-loss gate, one position at a time (`isBusy`), self-pause alarms, RTH 10:00-14:30 window. Fail-closed to the TELL, never to nothing: a missing context row means the tell's own order, never a skipped fire or an unreviewed flip. The override never changes size, the account or the order type. The tell's own result stays logged (amt_tell_trades and book A) so the control keeps running. The flipped trade uses the tell's real exit code; the 120-minute no-break exit and the FADE exit for a flipped trade use the tell components in the flipped direction (as the shadow book does).
## 4. Tests and rollout
Pure-function tests for `chooseBook`, the effective-trade `decideEntry`, `decideExit` with shadow rows and the stuck/stale checks (extend `scripts/test_amt_tell_orders.mjs`), a dry-run of the INSERT in a rolled-back transaction as the existing test does, then DeepSeek code review, a restart when the broker is flat, and verification on the next AGAINST fire. Revert = `override.enabled = false` and a restart.
## 5. Known open points
(a) Book C's flip uses the tell's FADE/timeout rules in the opposite direction, economically arbitrary (POC target is a v1.1 arm); (b) the reader is now on the order path for exits (a 5-minute stale alarm and the broker stop are the fallbacks); (c) the shadow row lags the live fill by seconds, so the flipped position's simulated entry differs from the real fill (the real fill is recorded; P&L uses the real fill as for the tell); (d) N is tiny: this is a live experiment on sim capital, not validated.

## 6. Amendment A1 after DeepSeek round N (full text `scratch/deepseek_response_20261103_185638.md`), and what was built
ACCEPTED and built in `server/services/amtTellOrders.js`: (1) the wait can no longer cross the freshness gate: `chooseBook` WAITs only while the entry bar has not completed and the fire is younger than `waitMs`; otherwise the TELL's own order goes out (fail to the tell, never to a skip; tested). (2) the re-link lookup after a crash searches either direction (`setup_type IN (LONG, SHORT)` at the fire's `entry_at`) and derives LINKED / LINKED_B / LINKED_C from the stored direction and stop. (3) `AMT_STUCK_ACTIVE` now tests tell-driven orders only (`order_state` NULL or LINKED); a new pausing alarm `AMT_OVERRIDE_STALE` fires when the shadow book a live LINKED_B/C order follows stops updating for 5 minutes or is CLOSED but unresolved for 3 (added to the restore-pause list). (4) attribution: `amt_tell_trades.order_state` records the book (LINKED, LINKED_B, LINKED_C); the Tell tab marks the order FLIPPED / EDGE STOP and 'the live order'; the board has a live override ledger (real P&L next to the tell's simulated result on the same fire). Not given a new setup_type: exact-name lists in `monitorSummary`, `setupExpiry`, `orderSweep`, `setupTypes` and the tests would each need touching; the tag is order_state. KNOWN POOLING: the Learning monitor's `AMT_TELL_STAGE2` arm (`scripts/learning_monitor_build.mjs`) and `REAL_TRADE_FILTER` still pool flipped trades under `AMT_TELL_LONG/SHORT` until they are split by `order_state` (OPEN_THREADS). (5) an OPEN shadow row is frozen to its code version (`reader.py` upsert guard). (6) automatic stops: `maxFlipsPerDay = 2`, the override turns itself off for the day on any shadow parity failure, every existing pausing alarm still pauses it; a checkpoint for the user after the first 5 live flips. Stop and direction are COPIED INTO the order at entry from the shadow book (one source of truth for the geometry, no re-implementation in Node); the shadow row is only the exit trigger, the broker stop and the 15:57 backstop are the safety net.
NOT CHANGED, with reason: the generic resolver backstop (`resolveSetups.js` AMT_TELL_ branch) is the same second exit writer the tell's own orders already have (stop walk on 1-minute bars, 15:57 expiry); it handles a flipped row by its name's direction. The tell's old test assertion that active_setups holds no tell rows was stale since live trading began and was replaced by a before/after comparison. 49 checks pass (12 new for the override).

## 7. Code review round O (full text `scratch/deepseek_response_20261103_191531.md`), audited
CLAIM REJECTED, MEASURED: "the flip is starved because book C only exists after the entry bar completes". `barbuilder.all_bars()` appends the FORMING bar (if it has volume) and `core.build_ctx` runs on it, so a fire whose entry bar is the forming bar gets its three books at once: measured on today's session, `build_ctx` 0.05 s for 1,286 bars, `simulate_fire` instant, books written True. The reader polls every second, so the books appear about a second after the tell row; the service waits up to `waitMs` = 20 s but only while the entry bar is still forming. First live fire will confirm the latency (check the reader log time against the tell row).
ACCEPTED: `AMT_OVERRIDE_STALE` now follows the reader's HEALTH (not wall-clock row age: a quiet 500-contract bar can take minutes) and also fires on a MISSING shadow row (the INNER JOIN hid it) and on a closed book whose order was not resolved within 3 minutes. The Tell tab names the flipped direction ('FLIPPED TO LONG'). A full service pass is now part of the order tests (runs every query against the real schema when there is nothing to act on).
KEPT, with reason: `SKIPPED_BOOKDONE` (the flip is already over when the order would be placed, so placing the TELL's order on an AGAINST fire would contradict the policy): this is a skip for a LOGICAL reason, not for missing information; the 'never to a skip' invariant is about infrastructure gaps (missing or late context), and the wording in section 3 is corrected accordingly. The worst-case loss of a flip is its stop distance (value edge plus one typical range, or the day's extreme so far plus a range when it entered beyond the edge), at 2 dollars a point; no extra cap is added (the tell itself has none by design); the daily-loss gate and one position at a time bound it. A book closing between the load and the insert produces an order the next `syncExits` flattens (bounded by its stop). Two fires cannot share an `entry_at` (one position at a time, one direction per bar). Re-link marks LINKED_C even with the override off after a crash-recovery: attribution only.
